# UX の点検（ux-screen）

引数は対象（`全体` / `To-Do` / `タイムライン` / `習慣` / `設定` … / `最小`）。無ければ聞かずに `全体`。
`最小` は機能を足す・画面を変える作業の中で、触った所だけ A・B・D を見る。

基準の正は `doc/PRINCIPLES.md`・`doc/RULES.md`・`doc/UI_CONSISTENCY.md`。ここは進め方と観点だけ。

## 進め方

1. **読む**: `doc/PRINCIPLES.md`、`doc/RULES.md` の触る節と「言葉」、`doc/UI_CONSISTENCY.md`
2. **コードで重複を洗い出す**（画面を見る前にやる。作りが何か所にもある所に、ずれとバグが集まる）
   - 同じ役割ごとに grep で一覧にし、挙動の違いを表にする。例:
     - 浮かぶ面の位置: `innerHeight`・`getBoundingClientRect`・`position: fixed`
     - 色: `backgroundColor`（`colorVars` を使っていない所）・`red-`・`orange-`（締切以外の赤・オレンジ）
     - 部品の自作: `type="checkbox"`・`<path`・`window.confirm`・自前の Esc / 外側クリック
     - 日付・時刻の欄、空の状態、追加欄（`InlineAddInput` の `onExpand` が無い所）
     - 言葉: `src/locales/ja.ts` と `en.ts` のキーの差、同じものを指す別の言葉
   - UI_CONSISTENCY.md に部品があるのに使っていない所、2 か所目なのに切り出していない所を出す
3. **画面で見る**: `npm run shots`。足りない場面は `scripts/shots/capture.mjs` の `SCREENS` に足す。
   閉じた画面だけでは A が写らないので、**開いた状態**（メニュー・カード・色パレット・日時の候補）と
   **端の場面**（画面の下・23 時台・0 時またぎ・長い名前・件数が多い・スマホのキーボード・英語）を撮る。
   PC / スマホ × ライト / ダーク
4. **指摘を出す**: 下の観点ごとに。1 件ごとに「ファイル:行・反する原則／決まり・直し方・同じ役割のほかの場所」。
   推測の指摘は捨てる（コードか画像で確かめたものだけ）
5. **Issue にする**: 重い順に。同じ根っこのものは 1 つの Issue にまとめる。本文に「完了条件」。
   すでにある Issue と重なれば足す（`gh issue list --search`）
6. **直す**: 1 Issue 1 worktree（CLAUDE.md の手順）。2 か所目からは共通部品に切り出す。
   同じずれが戻らないよう、テスト・lint・shots の確かめのどれかで止める
7. **撮り直して自分で見る**。確かめていない所は、確かめていないと書く

全体を一度に見るときは、観点ごとに分けて並行で回すと速い（利用者が workflow を頼んだときだけ）。

## 観点

| | 観点 | 見ること |
| --- | --- | --- |
| A | 届く・見える | 浮かぶ面が画面の端・下・夜の時間帯・キーボードの上でも全部見えて押せるか。開いた後に中身が伸びても収まるか（入らなければ面の中でスクロール）。下のナビ・タイマー・選択中のバー・トーストの下に潜らないか。重なり・切れ・押し出し。長い名前・多い件数・英語で崩れないか。タップは 44px |
| B | 同じ役割は同じ部品 | 位置決め・色の丸・日時の欄・閉じ方・確認・空の状態・追加欄・メニューが画面ごとに別に作られていないか。**機能の入口の重複**: 同じことが 2 か所でできて、項目・結果・言葉が違わないか |
| C | 同じ形は同じ動き | 丸を押すと ✓、行を押すと詳細、Esc・背景で閉じる、元に戻す（⌘Z・トースト）。長押し・右クリック・スワイプ・ホバー・キーだけの操作が無いか。キーボードだけで届くか、フォーカスが戻るか、意味のあるアイコンに `label` / aria があるか |
| D | 言葉 | RULES.md の「言葉」（締切・実行日・予定・記録・ラベル・タグ…）とずれていないか。同じものを別の言葉で呼んでいないか。ja / en の両方。ボタンの文字は短いか。説明文を常に出していないか。例文は学生・就活生向けか |
| E | 意味は 1 つ | アイコンの流用（PRINCIPLES.md の一覧）。赤・オレンジは締切だけ。同じ情報を 2 回出していないか。選ぶ前か決めた後かで出す情報を分けているか。色はベタ塗りでなく `gc-plan` / `gc-dot` / `gc-line` |
| F | 性質を混ぜない・数え方 | タスク / 習慣 / いつか / 買い物の出す場所と数え方。**同じ数（件数・達成率・時間・予定 N 件）が画面ごとに違う数え方になっていないか** |
| G | 状態と失敗 | 読み込み中・保存した・保存できない・オフライン・同期の競合・元に戻せる期間。失敗が黙って消えていないか |
| H | 場面 | 空・1 件・多数・長い名前・23 時台と 0 時またぎ・タイムゾーン・週の開始日・ダーク・スマホ・追加機能のオン／オフ・はじめて使う人 |

## 出すもの

- 観点ごとの指摘の表（重い順）と、作った Issue の番号
- 直したものは、撮り直した画面で確かめたかどうか
