# Chronograma — ネクストタスク（作業候補）

実装の正はコードと [`CURSOR_CONTEXT.md`](./CURSOR_CONTEXT.md)。リリース前の作業と決まりは [`IMPROVEMENT_TASKS.md`](./IMPROVEMENT_TASKS.md)。

## 性質の違うものを 1 つの To‑Do に混ぜない

入れるものは 4 種類あり、扱いが違う。

| 種類 | 例 | 扱い |
| --- | --- | --- |
| 締切・予定のあるタスク | 課題、ES、ゼミ資料 | 今日の計画に出す。締切を見せる。時間を確保する |
| 繰り返し | ジム、英単語 | 習慣か繰り返しタスク。毎日の一覧で何度も「未完了」にしない |
| いつかやりたい（Wish） | 人生で一度はやりたいこと、行きたい場所 | 期限なしで寝かせる。普段は見えない。気が向いたら「今日やる」に昇格 |
| チェックリスト | 買い物、持ち物 | 店で片手でさっとチェック。予定・統計・通知には関係させない |

Wish や買い物が「やるべきこと」の横に並ぶと選択肢が多すぎて手が止まり、終わらない Wish が罪悪感のもとになる。統計が買い物で膨らむと数字を信用されなくなる。

今の実装:

- リストの種類 `tasks` / `someday` / `checklist`。`someday`・`checklist` は期限系ビュー・今日の計画・統計・週のふりかえり・期限通知・カレンダー・日パネルに出ない
- 新規ユーザーは「いつか」「買い物」が最初からある。クイック追加の `@リスト名`
- チェックリスト画面（`ChecklistView`）: 大きいチェック、チェック済みは下、「全部戻す」「チェック済みを消す」、日付 UI なし
- いつか画面（`SomedayView`）: カード表示、「今日やる」で未分類へ移して今日の予定に、「かなえたこと」

| 優先 | やること | メモ |
| --- | --- | --- |
| P2 | 「今月かなえたいことを 1 つ」の提案（いつか画面） | |
| P2 | **未分類（受信箱）の整理**: 溜まったら「振り分け」（やること / いつか / 買い物 / 削除）を 1 件ずつ提示 | 何でもとりあえず入れてよい、を保ったまま散らからない |
| P2 | **繰り返し vs 習慣の整理**: ジムのようなものをタスクで作ったら「習慣にする」を提案。クイック追加で「毎日」「毎週月水」を解釈 | タスクの繰り返しと習慣が別々にあり、どちらを使えばいいか分からない |
| P3 | **使ってもらって確かめる**: 学生・就活生 3〜5 人に 1 週間。Wish・買い物をどこに入れたか、「すべて」を開いたかを聞く | 「いつか」「チェックリスト」という名前が伝わるかも |

## 公開前に直したい

## 余裕があれば

- `package.json` の `version` が `0.0.0`
- 初めて使う人向けの案内が無い
- push 購読の `endpoint` に入れられる URL を制限していない
- Edge Function の CORS がどこからでも許可（`*`）
- エラー監視の仕組みが無い

## 同期・連携

| 領域 | 今の状態 | 次 |
| --- | --- | --- |
| 同期モデル | 三方向マージ（`syncMerge.ts`）でタスク単位に `updatedAt` の新しい方を採用。同じタスクを両端末で同時に編集すると後勝ち（フィールド単位ではない）。他端末の変更はフォーカス復帰・60 秒ごとに取り込む。2 端末の実機では未確認 | Supabase Realtime で即時反映 |
| Google Calendar | 権限は `calendar.readonly` と `calendar.events`。古い接続は読み取りのみ | 公開には Google の審査、既存ユーザーの再同意 |
| スマホ | PWA・下部ナビ「今日」・計画画面の切り替えあり。iPhone / Android の実機での操作感は未確認（タイムラインのタッチ操作、キーボード表示時のレイアウト） | 実機で確認して直す |
| ドキュメント | スキーマは `supabase/migrations/` の番号順のファイル、一覧は `supabase/migrations/README.md`。ルート `README.md` と `doc/CURSOR_CONTEXT.md` もこれに合わせる | |
