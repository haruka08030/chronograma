原則は [`PRINCIPLES.md`](./PRINCIPLES.md)（記録が主役 / 締切は焦らせてよい / ごちゃつかせない /
性質の違うものを混ぜない / Google カレンダーに合わせる / 想定する利用者は学生・就活生 / PC が先 + PWA）。

実装で守り続ける決まり。作業は GitHub の Issue、アイデアと方向性は [`IDEAS.md`](./IDEAS.md)。

## デプロイ

スキーマを変えたら `supabase db push --linked --dry-run` で流れるファイルを確かめ、`supabase db push --linked` で本番に流す（適用履歴に記録される）。migration は何度流しても同じ形に書き、前の版のアプリが動いたままでも壊れない形（足すだけ）にするので、作業の途中で流してよい。番号は並行の作業とぶつかりやすいので、流す直前に `supabase migration list --linked` と dev の最新を見て付け直す。コミット済みの番号のファイルは書き換えない。

Edge Function は本番のアプリと同じ版でなければならないので、作業の途中では出さない。出すのは下の「main に出すとき」だけで、これから main に入れる dev の版から出す（`supabase functions deploy <名前>`）。

main に出すとき（DB と Edge Function は main へのマージでは出ないので手で出す。順番は migration → Edge Function → main へのマージ。新しいアプリが新しい列・関数を読む前にそろえる）:

1. 流れていない migration を出す: `supabase db push --linked --dry-run` で流れるファイルを確かめ、あれば `supabase db push --linked`。流したあと `--dry-run` で 0 件になったのを確かめる
2. 前回 deploy した後に変わった Edge Function を全部出す: 関数ごとに最後に deploy した時刻を `supabase functions list` の `UPDATED_AT` で見て、`git log --since='<その時刻>' --format='%h %ad %s' --date=iso dev -- supabase/functions/<名前> supabase/functions/_shared supabase/functions/deno.json supabase/functions/deno.lock` に 1 件でも出れば、dev の最新（このあと main に入れる版）を取り出した作業ツリーで `supabase functions deploy <名前>`（`_shared` が変わればそれを読む関数は全部）
3. 秘密や環境変数を足した・替えたら、先に入れる（Supabase の secrets・Vercel の環境変数。一覧は `doc/PUBLISHING.md` の 2）
4. dev を main にマージする

スキーマは `supabase/migrations/` の番号順のファイル、一覧は `supabase/migrations/README.md`。ルート `README.md` と `doc/CURSOR_CONTEXT.md` もこれに合わせる。

起動時に読まないもの:

- 同期と連携（`useSupabaseSync`・Notion・Canvas・Google への送信）は `AccountSync` にまとめ、ログインしてから読む（`AccountSyncLoader`。セッションが保存されていれば起動と同時に読み始める。一度読んだらログアウトしても描いたまま）
- CSV の取り込みは取り込むときに読む
- 起動時に読む JS（gzip）の上限は `scripts/build/startup-size.mjs`（CI で見る）
- `@supabase/supabase-js` はログインのセッションが保存されている・ログインから戻ってきた（`#access_token`）・アカウント欄でログインの欄を出した・ログインを始めた・ほかのタブでログインしたときに `loadSupabase()` で読む（`getSupabase()` は読み込み済みのときだけ返す。型以外で静的に読まない）
- 言語の文言は表示する言語の分だけ `i18n/config.ts` が読み（chunk は `locale-ja` / `locale-en`、日本語は date-fns の日本語も一緒）、画面は読み終えてから描く
- 最初から作る名前（「やりたいこと」/ Bucket list・「買い物」・初期のラベル）は `locales/builtinNames.ts`
- 前の版の初期の名前（いつか / Someday、`LEGACY_SOMEDAY_NAMES`）は同期で初期リストを見分けるときにも数え、その名前のままのいつかのリストは保存データの版 43 とサーバーの `044` で今の名前に直す（自分で付けた名前は変えない）

## テスト

- 全部のテスト（`npx vitest run`）は 10 コアの Mac で約 10 秒・CPU 約 60 秒（`--maxWorkers=50%` なら時間は同じで CPU 約 45 秒）。いくつもの作業を並べて動かすと負荷がそのまま積み上がる
- テストは `vmForks` で動く（`vitest.config.ts`）。ファイルごとに新しい vm（モジュール・jsdom・グローバル）で、プロセスはファイルをまたいで使い回す。vm の中の jsdom は `window.location` を書き換えられないので、読み込み直しは `lib/reloadPage.ts` を差し替えて確かめる。環境変数はファイルの終わりに戻す（`src/test/setup*.ts`）
- 作業の途中は、変えたファイルに関わるテストだけ流す: `npx vitest related <変えたファイル> --run`（または `npx vitest run <テストのファイル>`）。全部のテストはコミットの前に 1 回、`--maxWorkers=50%` で流す
- 日付・タイムゾーンを変えて全部流す `npm run test:tz` は 4 回分の重さなので、時刻を扱うところ（`src/lib/timeZone.ts`・`wallTime.ts`・`dayKey` まわり・タイムライン）を変えたときだけ流す
- CI: テストは 2 つに分けて同時に流す。タイムゾーンを決めた回（`test-tz`）は main に出す PR のときだけ流し、dev は毎晩 `.github/workflows/test-tz.yml` で流す（手で流すこともできる）。ビルドは static で 1 回だけ（manifest つき）、起動時の大きさはその manifest で数える

## 通知

通知は「放っておくと逃すこと × 今なら手を打てる」ときだけ。1 日 3〜6 回が目安。

- 朝のまとめ: 今日の予定の数・今日の締切・締切切れを 1 通
  - 2 行目に昨日の数字「昨日: 予定 5 件中 3 件・予定外 40分 ・ 記録 4時間10分」（夜のまとめと同じ言葉で数字だけ。数えた予定が無ければ予定の部分、予定外が 0 なら予定外、記録が無ければ記録の部分を出さず、どちらも無い日は行ごと出さない）
  - 昨日の数は今日の計画で昨日を見たときの見出しと同じ（「言葉」の「予定 N 件中 M 件」。サーバーは利用者のタイムゾーンの昨日を `wrapUp.ts` で数える。読めなければ昨日の行だけを出さずに送る）
- 予定の前: 開始 ◯ 分前
  - 「記録を始める」ボタン付き（Web Push・タブを開いている間の通知とも）
  - 押すとアプリを開いて、その予定のタイマーを ▶ と同じく始める（元の予定の id を持つ。`startTimerFromNotification`）
  - Service Worker が 1 回きりの印（launch）を付けて開き、印があるときだけ始める（印の無い `?start-timer=` はその予定の詳細を開くだけ）
  - 別のタイマーが動いていれば「◯◯を止めて△△の記録を始めますか？」と聞いてから切り替え、同じ予定を計っていれば何もしない
  - 予定の終わりを過ぎていた・済んでいたら始めずに詳細を開く
  - 本文を押したときは今までどおり詳細
- 締切の前: 前日 20:00、時刻つきは当日 3 時間前
- 予定のあと: 終わりに「予定どおり / 記録する」（設定でオフにできる）。その予定から始めた記録（`source_task_id`）がその日にある・今その予定を計っているときは出さない（`dropRecordedPrompts`。サーバーは送る前に読み、読めなければ今までどおり送る）
- 夜のまとめ（既定オフ、オンにすると 22:00）: 決めた時刻から 60 分の間に 1 通
  - 「今日: 予定 4 件中 3 件・予定外 1時間 ・ 記録 5時間」と数字だけ（数えた予定が無い日は予定の部分を出さない）
  - 数え方は今日の計画の見出しと同じ（「言葉」の「予定 N 件中 M 件」。サーバーは `wrapUp.ts`）
  - 記録が 0 の日は送らない
  - 残りの件数は出さない（残りは次の日の「やり残し」で動かす）
  - 押すと今日の計画を開き、スマホはタイムラインの面を出す
  - 下の気分の記号は時刻の前でも出す（PC はそこまでスクロールする）
- タイマーの止め忘れ: 3 時間を超えたら
- 「あと何分」の時間（集中タイマー）: 付けた終わりの時刻に 1 通と音 1 回。タブを開いている端末はちょうどの時刻に出し、全部の購読に知らせた印を付ける（ほかの端末へ遅れて重ねない）。閉じている端末へは Web Push（5 分ごとの回なので最大 5 分ほど遅れる。30 分より遅れたら送らない）。通知の「止める」は止め忘れと同じ。記録は止めない
- タスク・予定ごとの通知（開始 ◯ 分前・締切の ◯ 前）を決めたら、既定の代わりにそれを使う
- 記録の帯の凡例の「ラベルなし」と設定のラベルの「直近 30 日でラベルなしの記録」は、押すとその記録を 1 行ずつ（題名・時刻。設定は日付も）並べ、行のラベルのチップでその場で付ける。付けた行も閉じるまで残る（押し間違いを直せる）。題名を押すと詳細（`UntaggedLogList`）。設定のラベルなしはラベル名も色も無い記録（睡眠は除く、`isUnlabeledLog`）
- 1 日の気分: 今日の計画の下に 5 つの記号（○ ◔ ◑ ◕ ●、とても悪い〜とても良い。名前は読み上げとツールチップだけ）を、今日を見ていて夜のまとめの時刻（未設定なら 17:00）を過ぎたとき・通知から開いたとき・その日に付けた後に出す（To-Do が無い日・残りが 0 件の日も）
  - もう一度同じ記号を押すと外れる
  - 記号を押すと一言の欄（1 行・任意・140 字まで。離れた・Enter で残り、Esc で戻る）が開く
  - 過ぎた日の今日の計画の見出し（睡眠の横）に記号を小さく出し、一言があれば押すと開く
  - 今日・これからの日の見出しには出さない
  - 日ごとに端末間で同期する（`day_moods`、`src/lib/dayMood.ts`）
  - 統計・週のふりかえりの数には入れない

## 操作

### 閉じ方・削除・確認

- 外を押すと閉じる面は、重なっているときは一番上の 1 枚だけを閉じる（Esc と同じ）
  - 下から出るシート（ActionMenu・時間を決める・締切の日時・スマホ幅の予定のカード・ラベルのカード）と、全面を覆う背景のあるもの（詳細・ドロワー・ダイアログ）は、外（暗い背景・シートの外）を押すと閉じるだけで、その押下は下のボタン・行・タブ・タイムラインに届けない（クリック・指のあとのクリック・長押し・ドラッグも始まらない）
  - 全面の背景のあるものは背景を押したときだけ閉じる
  - PC の小さなカード・メニュー・ピッカーと時刻の候補は、閉じて押下はそのまま下へ通す（別の予定を押すとそのカードに替わる）
  - どれも `useDismiss`（`swallow`・`backdrop`。押下を止めるのは `lib/swallowPress`、下からのシートの幕は `ui/SheetBackdrop`）
- 削除は確認なしで消し、「「名前」を削除しました · 元に戻す」を出す（タスク・セクション・記録・睡眠・習慣・リスト・ラベル・Google の予定・学期・時間割の授業・引き落とし・期限）。Google の予定はトーストが消えるまで Google への削除を待つ（タブを閉じるときは待たずに送る）
- ⌘Z（Windows は Ctrl+Z）は直前のデータの操作を 1 回戻し、⌘⇧Z でやり直す（`store/undo.ts`。どちらも 50 回まで、`MAX_UNDO`）
  - 新しい操作をするとやり直しの履歴は消える
  - 入力欄にいる間はブラウザの文字の取り消しが先
  - 戻すのは変わった行・設定だけで、記録中のタイマーと見ている画面は戻さない
  - ほかのタブの変更を取り込んでも履歴は残す（取り込んだ行は戻さない）
  - 「元に戻す」のトーストはその操作だけを戻す（`undoOperation(id)`。あとの別の操作は残す）。あとの操作も同じ行を変えていたら、その操作が変えた項目だけを戻す（`rebaseEntry`）
- 確認を出すのは戻せないものだけ: ゴミ箱を空にする・完全に削除・アカウント削除・連携の解除
- アカウントの削除は 10 分以内にログインしたセッションからだけ（`account/reauth.ts`）。古ければ設定のアカウント欄にメールのコードを送る欄を出し、コードでログインし直したらそのまま消す
- 結果は画面下の通知（戻せるものは「元に戻す」付き、`src/lib/notify.ts`）。入力の誤りは赤字＋押せないボタン。`alert` は使わない
  - 通知（元に戻す・移動・Canvas の提出済み）は 1 つの置き場に下から積み、同時に出ても重ねない（`ui/Toast` の `ToastStack`・`Toast`。読み上げは `role="status"`）
- ダイアログの入力（習慣・引き落とし・期限・学期・時間割の授業・ご意見）は、外を押す・Esc で閉じても書きかけを残し、次に開いたら続きから。保存・削除・キャンセルで捨てる（`useDialogDraft`）

### To-Do の行

- To-Do・習慣の丸を押して完了・達成にすると、行はその場に済んだ見た目（✓・灰色の名前）で 0.6 秒残り、0.2 秒で縮んで消えてから完了の欄へ移る（今日の計画の「完了 N 件」の数が増える）
  - 残っている間・縮んでいる間にもう一度押すと取り消す
  - 続けて押した行はそれぞれの時間で移る
  - 完了を外すときは待たない
  - 動きを減らす設定でも 0.6 秒は残し、縮まずに消える
  - To-Do の一覧・カレンダーの日のパネルなどの To-Do の行も同じ時間だけ残す（縮むのは今日の計画だけ。終えた行がその場に残る画面があるため）
  - 待っている間に画面を離れても完了にする（`useDeferredComplete`）
- タッチでタスクの行（To‑Do・今日の計画・カレンダーの置き場・検索結果）を長押しすると、行が浮いて（影と少しの拡大。視差効果を減らす設定では拡大しない）選択に入る。押さえたまま別の指で他の行をタップすると、その行も選択に入る。動かさずに離したら選んだ状態で終わり、選択バーを出す（`lib/touchLift`・`useRowLift`）
- To‑Do の手動の並びでは、浮かせたまま指を動かすと、選んでいる行をまとめて並べ替え・リストやセクションへ移す（PC の複数選択のドラッグと同じ。`AppTouchSensor`）。件数はつかんでいる行のバッジ。リストの帯・計測の帯は指を動かしてから出す。サブタスクは 1 行だけ運ぶ。浮かせている間は行の横払い・画面の横払い（ドロワー）を取らない
- To-Do の行のドラッグは、PC は 5px 動かしたら始まり（`MouseSensor`）、タッチはつまみなら 140ms、行の長押しなら 450ms（どちらも 8px 動いたら取り消す。`AppTouchSensor`・`useAppDnd`）
- 行を横にドラッグすると階層を変える（横の動きが縦より大きいときだけ。複数選択のドラッグでは変えない。`lib/taskDragIntent.ts`）
  - 右へ 24px（`NEST_DRAG_DELTA`）以上で、すぐ上の兄弟の子にする（兄弟が無ければ何もしない）。いつかのリストでは子にしない
  - 右へ動かしている間は、親になる行に L 字の線を出す（`NestDragGuide`）
  - 左へ 24px（`UNNEST_DRAG_DELTA`）以上で、サブタスクを 1 段上げる（元の親のすぐ後ろ）
- 複数選択した行をドラッグすると、選んだ行をまとめて運び、件数のバッジを出す。手動の並び以外の行と時間未定のタスク（`CalendarTaskDock`）からのドラッグも同じ
  - 週・日のタイムラインに落とすと、落とした時刻から順に重ならないよう積む
  - 月のマスに落とすと、全部の実行日をその日にする（時刻はそのまま）
- チェックリストのチェック（`toggleChecklistTree`、`lib/listTree.ts`）: 子のある行は子ごと付け外しする。子が全部付いたら親も付き、子を外すと親も外れる。付けた子は親の下に残す
  - 下の「チェック済み」に「すべて戻す」（`uncheckTasks`）と「チェック済みを消す」
- 完了の印は To-Do が丸、チェックリストが四角、いつかが ☆ / ★（`CompletionCircle` の `shape`）
- To‑Do の行はカーソルを乗せるとアーカイブと削除のアイコンを出す（タッチの md 以上は常時、スマホ幅は … のメニュー）
- タスクの詳細の右上（スマホは上の帯）の … で、行の右クリックと同じタスクのメニューを開く（記録には出さない。「編集」は出さない）。PC の行で右クリック・ホバー・キーでしか出ない操作（複製・明日へ回す・記録を始める・リストへ移す、夢のかなえた・段を移す）も、行を押して詳細から見えるボタンでできる。消した・アーカイブしたら詳細も閉じる
- 完了した To‑Do はリストや「すべて」などの一覧の下に出さず、To‑Do ナビの「完了済み」（アーカイブ・ゴミ箱の上）に全リスト分を集める。完了した日ごとに新しい順、行にリスト名（`CompletedTasksView`）。チェックリストの「チェック済み」といつかの「かなえたこと」はリストの下に残す
- 検索結果・完了済み・アーカイブ・ゴミ箱は、新しい順（検索は当たった順）に 100 行だけ描き、下の「さらに表示（残り N 件）」で 100 行ずつ足す（`useShowMore`・`ShowMoreButton`）。件数は全部の数。最後の行で ↓ を押しても足して次の行へ進む。⌘A・Delete は描いている行だけに効く
- 検索は To‑Do・予定の行と記録（タイマー・後から入れた記録・睡眠）を混ぜない。To‑Do の下に「記録 N 件」と「記録を見る」だけを出し、押すと新しい順に題名・日付・時刻の 1 行で並ぶ（押すと詳細）。⌘K のパレットと検索欄の Enter は To‑Do・予定だけ（`searchTasks` / `searchRecords`）
- To‑Do の並び順（見出し右のボタン）はリスト・期限別ビュー・色ラベルごとに覚える（鍵は `sortKeyOf`）。選んだことが無いところは手動（締切で集める「近日中」「締切切れ」は締切順）。リスト内のタグの絞り込みはそのリストの並び順を使う。優先度で並べたときは同じ優先度の中を締切の近い順に。メニューは共有のメニュー部品（スマホは下から出すシート）。手動以外でもつまみの幅を空けて、行の文字を動かさない
- タスクの行は題名を押しても行と同じで、待たずに開く（To-Do 一覧は PC もスマホも詳細。今日の計画は PC は詳細、指は短いシート、`useOpenTaskRow`）。タスクの名前の変更は詳細の題名か、題名にフォーカスして F2（一覧のダブルクリックでは変えない）。詳細のサブタスクの行は押すと名前の変更

### メニュー・複製

- タスクの右クリック（PC）の先頭は指で押したときのシートと同じ並び（1 件なら「時間を決める」（時間未定のとき）・今日やる / 明日へ・「記録開始」、区切ってその下に実行日・締切）
- タスクの右クリック・指で押したときのシートの「締切 ›」「実行日 ›」は右に今の値（「今日 18:00」「10/10 (土)」。選んだタスクで値が違えば出さない、`menuDateHint`）。「締切 ›」の最後の「日時を指定…」で日付と時刻を一度に選ぶ（`DueDateTimeMenu`）
- タスクのメニュー（PC の右クリック・選択バーの「操作」・予定の右クリック）の「複製」は、同じ日・同じ時間・同じ中身のコピーを元のすぐ後ろに作り、1 件なら詳細を開く（Google カレンダーの「複製」と同じ。画面の名前は「コピー」）
  - 子も写す（ゴミ箱・アーカイブの子は除く）
  - 完了・持ち越し日数・移した予定の控え・毎週の繰り返しの印は引き継がない（毎週の予定の 1 回を写すと、ふつうの予定になる）
  - 記録・睡眠は写さない
  - 親と子を一緒に選んでも子は 1 つ
  - 取り消しは 1 回（`duplicateTasks`・`duplicateTaskTrees`）
  - Google の予定のコピー（月・スケジュール・日の一覧・タイムラインの右クリック、書き込める予定だけ）は同じ日・同じ時間（開催時間）に題名・メモ・自分で付けた色を写して Google に 1 件作る（繰り返しの予定はその回だけ、`duplicateGoogleEvent`）
- カレンダー（週・3 日・日の時間の格子、終日の行、月のマス）で ⌥（Windows は Alt）を押しながら予定・タスクをドラッグして離すと、元は動かさず、置いた日・時刻に複製を置く（中身の決まりは「複製」と同じ。移した控え・持ち越しは付かない）
  - 押している間は元を薄くせずその場に残し、カーソルをコピーの形にする
  - 記録・習慣の枠・Google の予定は ⌥ を押して離しても何もしない（動かしもしない）
  - 取り消しは 1 回（`lib/dragCopy.ts`）

### 追加欄・名前の変更・キー操作

- タスクの追加欄は追加後も開いたまま続けて書ける（空の Enter・Esc・外を押すと閉じる）。入れ物（リスト・セクション）を作る欄は 1 つで閉じる。表記は「タスクを追加」
- 「＋ セクション」は名前の入力から始め、名前なしで離れたら作らない。タスクも名前なしで離れたら消す（ゴミ箱・取り消し履歴に残さない）
- タスク詳細のタグ・サブタスクは、確定せずに外を押しても追加する
- 名前の変更: PC はダブルクリックかホバーで出る鉛筆、スマホは鉛筆（リスト・セクション共通）
- Enter の判定は `isSubmitEnter`、Esc は `isCancelEscape`（`src/lib/keyboard.ts`）。`src/components`・`src/hooks` の素の `e.key === 'Enter'` / `'Escape'` は lint で止める（入力欄でないボタンなどは理由を書いて `eslint-disable-next-line`）。ダイアログ内の入力欄でも、欄が使わない Esc でダイアログを閉じる

### 習慣

- 習慣のカードは右クリック（タッチは長押し）で「編集・今日の記録を付ける / 外す・休む・アーカイブ・削除」（`HabitContextMenu`、To‑Do と同じ `ui/ActionMenu`）
  - 習慣の詳細の下は 編集・休む（今日から。この日だけ・カレンダーで選んだ日まで。休みの日は「休みを外す」）・アーカイブ・削除。休むはメニューと同じ（`useHabitRestEntry`）
  - 長押しは `useLongPress`
  - 週の表の日のマスで開くと「休む」はその日から、行で開くと今日から
  - タイムラインの習慣の枠も右クリック・長押しで同じメニュー（「休む」はその枠の日から。習慣そのものの削除は出さず、格子に置いた時刻ひとつの習慣には「習慣の段に戻す」を足す。削除は習慣の画面と詳細から）
- タイムラインの習慣の枠を押すと小さなカード（`timeline/HabitSlotPopover`）: 上の並びに ✎・「この日は休む」（一時停止のアイコン）・格子に置いた日は「習慣の段に戻す」（上向きの矢印）・閉じる。下に、始まった枠は ✓ で予定どおり達成・取り消し、終わる前は ▶ 記録を開始。✎・メニューの「編集」は画面を移らず、開いている画面の上に習慣の詳細を編集から開く（`HabitEditHost`、App に 1 つ）
- タイムラインから開いた編集では、今日以降の枠なら一番上にその日の時間と「時間を変える」を出し、その場で時間を直せる（`HabitDetailSheet`・`timeline/HabitTimeEditor`・ストアの `setHabitTime`）:
  - 直す日は「この日だけ」か「これ以降の◯曜日」、◯曜日は「ずっと」（曜日ごとの時間 `weekdayTimes` を変える。今日より前は `pastRules`、今日〜その日の前の同じ曜日は日ごとの時間で前のまま、その日から先の同じ曜日の日ごとの時間は外す）か日付まで（その曜日の日ごとの時間を期限まで入れる、既定は 4 週あと）。時間を決めていない習慣（その日だけ格子に置いた枠）はこの日だけ
- 今日の計画の習慣（`PlannerHabits`）: To-Do の欄のすぐ下（「To-Do から追加」より上）に、To-Do と同じ高さの行で出す
  - 行はその色の丸（押すと達成・外す）・名前（押すと画面を移らずに習慣の詳細、`requestHabitDetail`・`HabitEditHost`）・右に時間外 / 目標の進み（「12/30 分」）と、週に◯回は「今週 1/2」（ほかの日で満たしたら「今週は達成」）、それ以外は時刻（「07:30」「18:00–19:00」）・▶（今日だけ）
  - 時刻のある習慣を時刻順、その後に時間なし（習慣の順）
  - 達成した習慣と今週は達成の習慣は、終えた To-Do と同じ一番下の「完了 N 件」（閉じた状態）にたたむ
- タイムラインの習慣: 始まりと終わりを決めた習慣は予定の列の枠
  - 始まりの時刻と「1 回の目標」がある習慣も、最初から開始〜開始＋目標の枠（習慣の段には出さず、「時間に置く」「習慣の段に戻す」も出さない）
  - 始まりの時刻だけで目標の無い習慣は長さを持たないので格子に置かず、終日の行の下の「習慣」の段に時刻つきのチップ（「07:30 ストレッチ」、時刻順）で出す（`WeekHabitRow`・`pointHabitsOn`）
  - 時間を決めていない習慣も、やる日にその後ろへ時刻なしのチップで出す（習慣の順。週に◯回・休み・アーカイブは今日の計画と同じ。✓「達成にする」は今日と過ぎた日だけ、格子へは置けない。`untimedHabitsOn`）
  - 始まった時刻からチップの ✓ で予定どおり達成・取り消し
  - 押すと枠と同じ小さなカード、右クリック・長押しで同じメニュー
  - チップをその日の格子へドラッグすると、その日だけ落とした時刻からの枠になる（長さは既定の予定の長さ。`habits.timeOverrides` に終わりも入れる）
  - 枠にした日は段から消え、ほかの枠と同じく動かす・伸ばす・✓ ができ、✓ の記録は枠の長さ
  - ほかの日・ほかの落とし先（終日の行・リストなど）には置かない
  - チップを押したカードの「時間に置く」でも、その日だけ習慣の時刻から同じ長さの枠になる（指ではドラッグできないので。達成した日は出さない、`placeHabitSlot`）
  - 置いた枠は、格子より上（習慣の段）へドラッグするか、枠のメニューの「習慣の段に戻す」でその日のチップに戻る（その日だけの時間を消す、「元に戻す」付き。`unplaceHabitSlot`）
  - PC はその週を全部置いても段を落とし先として残す
  - スマホ幅はチップが無ければ段を出さず、格子より上へ持っていっても戻さない（戻すのは長押しメニューだけ）
  - その週に 1 つも無ければ段を出さない
  - 今日の計画の 1 日表示には出さない（左の一覧に出る）
- 習慣の休み: 「休む ›」で「この日だけ」かカレンダーで選んだ日まで（1 回で 366 日まで）
  - 休みの日のメニューは「休みを外す」（その日から先に続く休みだけを外し、前の日は残す）
  - 休みの日は予定の日に入らない（`isHabitScheduledOnDate` が false。今日の計画・タイムラインに出ず、連続は止まらず数えもせず、達成率・週のふりかえり・月のカレンダーの分母から外れる。マスは予定の無い日と同じ点）
  - 週に◯回は、その週に求める回数を休みを除いた日数までにし、まるごと休みの週は数えない（`habitWeekRequired`）
  - 端末間で同期する（`habits.rest_dates`、日ごとに合わせる）
- 習慣の画面の週の表の「週に◯回」の行は、7 日の丸ではなくその週に求める回数分の丸（休みを除いた日数まで）
  - やった日（達成・時間外）を古い順に塗り、残りを空けて、後ろに「好きな日に」を添える（丸は日の列と関係しない）
  - 空いた丸を押すと今日の達成（今日がその週にあり、今日まだやっていず、休みでないときだけ。ほかは押せない）、塗った丸を押すとその日の達成を外す
  - 別の日に付けるのは詳細の月のカレンダー（`TimesPerWeekSlots`）
- 習慣の表の右端は今の連続。0 のときは最長（「最長◯日」）、どちらも 0 なら出さない
- 習慣を作った・頻度や時間（曜日ごとの時間・時間の目標も）を変えた日より前の日は変えない（`Habit.pastRules`、`until` より前の日はその設定）
  - 作ったときは `{ until: 今日, off }` で、今日より前は予定の日に入れない（タイムライン・今日の計画・予定 N 件・達成率に出さない）
  - 変えたときは前の設定を `until: 今日` で残し、今日から新しい設定（同じ日に何度変えてもその日の最初の前の設定を残す）
  - 日の判定（`habitDayStatus`・枠・予定の日）は `habitAsOf` でその日の設定、週に◯回の回数はその週の最後の日の設定（`habitAsOfWeek`）
  - アプリと Edge Function で同じ
  - 端末間で同期する（`habits.past_rules`）
- アーカイブした習慣は今日の計画・習慣の一覧と要約・タイムライン・週のふりかえりから外れ、達成日は残る（`isHabitScheduledOnDate` が false）。習慣の画面の下の「アーカイブ N 件」（閉じた状態）から「戻す」。端末間で同期する（`habits.archived_at`）
- 習慣の削除は To‑Do と同じくゴミ箱へ（確認なし・「元に戻す」付き。`Habit.deletedAt`）。ゴミ箱の習慣はどの画面・統計にも出さず（画面は `selectLiveHabits` から読む）、達成日は残る。ゴミ箱の画面ではタスクの上に習慣の行を出し、「戻す」で達成日ごと戻る・完全に削除（確認あり）。端末間で同期する（`habits.deleted_at`）

### 日付・時刻の欄

- 日付の入力はすべて `DateField`（締切と同じカレンダー、画面に固定して出す）。ブラウザ標準の日付欄は使わない
- 日付を選ぶ月のカレンダー（`DatePickerBody`）の見出しは « ‹ › »（前の年・前の月・次の月・次の年）。日の格子は常に 6 週で、月を送っても高さが変わらない。キーは ←→↑↓ で日・週、PageUp / PageDown で月、Shift＋PageUp / PageDown で年
- 予定の時間帯の欄（タイムラインのカード・タスクの詳細・追加欄・「その他の時刻…」・予定のテンプレート・時間割の時限・習慣の時間帯）は、開始を変えたら長さを保って終わりもずらす（Google カレンダーと同じ。日の終わりを越える分は 23:59 で止める。`endAfterStartEdit`）
  - 終わりが空なら、開始を入れたときに埋める（タスクの詳細は開始＋見積もり（無ければ既定の予定の長さ）、「その他の時刻…」は選んでいる長さ、テンプレート・習慣は既定の予定の長さ、時間割は 90 分）
  - 記録は実際の時刻なので開始だけ直す
- 終わりの時刻の候補は開始の 15 分後から並べ、それぞれに長さを添える（「11:30 1時間30分」、`TimeInput` の `durationFrom`）。予定は日をまたげないので 23:59 まで、記録・睡眠は翌日の開始の手前まで 1 周（`overnight`）。終わりの日を別に選ぶ欄（記録の詳細・止め忘れ）はふつうの候補
- 記録の詳細で開始の日を動かしたら、日をまたぐ記録は終わりの日も同じ日数ずらす（`endDateAfterStartDateEdit`）
- 時刻のある完了前の To-Do は、見積もりを変えたら終わりも開始＋見積もりにする（23:59 まで）

### 記録の入力

- 記録の保存ボタンは「記録する」（完了も兼ねるなら「記録して完了」）
- 記録を入れるフォームは 1 つの形: 題名・時刻 1 行（開始 – 終了、`LogTimeRow`）・ラベルのチップ（`TimeLogTagField`）。日付は出さず、終了が開始より前なら「翌日まで」。記録パネルの「後から記録」と通知の「記録する」（`CompleteWithLogModal`、メモも付く。ラベルの初期値は元の To-Do・予定のラベル）で同じ

### スクロール・拡大縮小

- 画面を切り替えて戻ったら、離れたときのスクロール位置から出す（To‑Do はリスト・ビュー・色ラベルごと、月・予定リストは表示の月・日ごと、週のタイムラインは表示の週ごと。今日の計画・統計・習慣・完了済み・アーカイブ・ゴミ箱・設定は画面ごと）
  - アプリを開いている間だけ覚える
  - 行き先を指定して開いたとき（設定の欄へ・セクションへ）はそちらを優先
  - 検索結果は覚えない
  - 週のタイムラインは覚えた位置が無ければ今・朝へ（`useRememberScroll`）
- 画面は拡大縮小しない（viewport の `maximum-scale=1, user-scalable=no`、`html` の `touch-action: pan-x pan-y`、iOS の gesture イベントは `boot.tsx` で止める）。タイムラインの 2 本指のピンチだけは 1 時間の高さを変える（30〜180px、既定 60px。指の下の時刻は動かさない。端末に残し同期しない `chronograma_hour_height`。`usePinchHourHeight`）。ピンチを始めると 1 本指のドラッグ・長押しは取り消す

## ラベルと色

### リストとラベル

- To‑Do はリストで分けず、ラベルで分ける。リストはいつか・チェックリストだけ（作るときに種類を選ぶ）。To‑Do の行はすべて未分類（表示名「To‑Do」）に入り、ナビは「すべて」などのビュー → ラベル（＋「ラベルなし」）→ いつか・チェックリスト → 完了済み・アーカイブ・ゴミ箱
- 前の版のリスト（フォルダ）・前の版の端末から同期で届いたもの・取り込んだバックアップの `tasks` 種類のリストは、読み込んだときに畳む（`lib/foldTaskFolders.ts`）: 中のタスクは未分類へ（セクションの外へ）。色の無いタスクには、リスト名と同じラベルがあればその色、リストの色にラベル名があればその色、どちらも無ければリストの色にリスト名のラベルを作る。Canvas は科目名のラベル。未分類のセクションも外す
- いつか・チェックリストのタスクは、期限別ビュー（今日・近日中・期限切れ・すべて）・今日の計画・統計・週のふりかえり・通知の件数に入れない（そのリストを開けば見える。`unplannedListIds`、`lib/listKind.ts`。Edge Function の `daily-reminders` も同じ）
- ラベル＝色に付けた名前。To‑Do と記録で共通。空は「ラベルなし」（To‑Do のタグの空は「タグなし」）
- 編集は「ラベルを編集」（✎ と同じ画面）と To‑Do ナビの丸のカード。設定は使用時間・並べ替え・その画面を開くボタンだけ
- To‑Do ナビの「ラベル」欄: タスクに付けた色ごとにラベル名（無ければ Google の色名）と未完了数。押すと「すべて」をその色で絞る。ラベルがあるときだけ、その下に色の無い To‑Do の「ラベルなし」（`NO_LABEL`）を出す（`src/lib/todoColorLabels.ts`）
- To‑Do ナビの「ラベル」欄の丸を押すと、その行の横に名前・24 色・削除のカード（スマホは下からのシート）。Enter・外を押すと保存、Esc は保存せずに閉じる。保存は「ラベルを編集」と同じ（`saveLogLabels`）で、削除は確認なしで「元に戻す」。名前の無い色は名前を書くとその色のラベルになり、色を変えるとその色の予定・タスク・記録も新しい色へ。行（丸以外）を押すと今までどおり絞る（`labels/ColorLabelCard.tsx`）
- ラベルの色を変えたら、その色の予定・タスクも新しい色へ
- 記録・To-Do・予定はラベルを id で指す（`Task.labelId`、`lib/labelIds.ts`）。ラベルの名前・色を変えても行は書き直さない（`updatedAt` を変えない）。行の名前（記録の `category`）・色（To-Do・予定の `color`）は前の版の端末が読む写しで、端末の中ではいつもラベルの今の名前・色にそろえる（`relabelTasks`。⌘Z も同じ）。名前・色を直す操作は id を外し、名前・色から付け直す
- リスト（いつか・チェックリスト）の色もラベルの色から選び、丸のヒントにラベル名（無ければ色名）を出す（`useLabeledSwatches`）。リストの色はリストの目印（ナビ・メニュー）にだけ使い、中のタスクには写さない。色を付けていないタスクはカレンダーでも「ラベルなし」の灰色
- 色の丸は `ui/ColorSwatches`（24 色・選択はチェック）。ナビのリストの色は 6 列、他は 12 列（スマホ幅は 6 列）。自由な色の画面（`SelectColorDialog`）は別

### 記録・習慣の色

- To‑Do から記録を作るとき、分類は To‑Do のラベルから取る。名前の無い色も色のまま引き継ぐ
- 習慣の色＝ラベル。習慣の記録（達成・タイマー）は習慣の色のラベルになり、タイトルからの推定より優先する。名前の無い色は色のまま。習慣の色選びもラベル付きの色選び（`labels/ColorPalette`）
- 記録の内訳（月のマス・今日の記録・週のふりかえり）はタイムラインと同じ色でまとめる: ラベル名 → 名前の無い色 → ラベルなし（`recordLabelKey`）

### タグ・クイック追加

- To‑Do のタグは常に使える。タスク詳細のタグ欄はいつも出し、クイック追加の `#タグ` はいつも読む。行・統計の「タグ別」はタグがあるときだけ出す。タグは色を持たず、記録の分類・統計の色には入らない
- クイック追加に書いた URL は題名に入れず、日付・時刻の読み取りにも使わずにメモへ入れる（URL だけなら題名は URL の短い形）。ほかのアプリの「共有」（Android の Chrome・Edge のインストール済み PWA だけ）は追加欄に「タイトル URL」を入れて開くだけで、足すのは利用者が確かめてから。1 行に収まらない本文はメモの先頭に入り、欄の下に「共有した本文はメモに入ります」と出す
  - メモは本文が先で、URL はその下に 1 行に 1 つ（`splitUrls`。URL だけのときの題名は `shortUrlLabel`）
- クイック追加の日時は空白で区切った語から読む（`parseQuickAddTitle`、`lib/parseQuickAdd.ts`）。時刻の範囲だけは題名にくっつけてもよい（「バイト17時〜22時」）
  - 表示言語を問わず読む: today・tomorrow・tmr・tonight・曜日（fri）・noon・next fri（来週の金曜）・this fri・this week / next week（その週の日曜が締切）・this weekend（土曜）・in 2 days・in 3 weeks・in a week・Dec 5・5 Dec・Dec 5 2027（`readEnPhrase`）、9/30・2027-01-15、15:00・3pm、範囲 15:00-16:30・3pm-4pm、長さ 1h・45m、締切の印 by・due、繰り返し every fri
  - 表示言語が日本語のときだけ読む: 今日・明日・明後日・◯曜・来週◯曜・10月3日・3日後・1週間後・今週中・来週中、15時・15時半・午後3時、範囲 15時〜16時半・17時から22時、長さ 1時間・30分、締切の印 まで・締切・期限、繰り返し 毎日・毎週金
  - 時刻があれば予定（実行日と時間帯。長さを書かなければ既定の予定の長さ `defaultBlockMinutes`）
  - 日付だけなら実行日。締切の印か「今週中」「this week」を付けると締切
  - 締切の印と時刻を一緒に書くと締切の時刻にし、予定にはしない
  - 月日だけの日付が 60 日（`QUICK_ADD_PAST_DAYS`）より前に過ぎていれば来年

### 連携の科目

- Canvas の課題は科目名のタグ、Notion の行はデータベース名のラベルを付けて未分類に入れる。ラベルは新しく作るときだけ作る（名前を変えたラベルを取り込みのたびに作り直さない）
- 時刻のある予定（To-Do でない予定・Google の予定）のカードに、その授業の科目（LMS から取り込んだ課題の最初のタグ）の未完了の課題を締切順に 3 件まで出す（それより多ければ「ほか n 件」）
  - 押すとその課題の詳細を開く
  - 科目は、カードで選んだつながり（予定の名前ごと。「つながない」も覚える）→ 予定の名前か予定のラベル名が科目と同じ（全角半角・大文字小文字・空白の違いだけ同じに数える。部分一致ではつながない）の順で決める
  - つながる科目が無い予定（授業でない予定も）には何も出さない（科目を選ぶ欄も出さない）
  - 課題が無い・「つながない」を選んだ予定にも何も出さない
  - 課題を出している予定は、見出しの横で科目を選び直せる（「つながない」も）
  - つながりは端末間で同期する（`user_course_links`、`src/lib/courseLinks.ts`）

### 子の進み具合・やりたいこと

- 子のある行は、どのリストでも題名のすぐ右に進み具合「済/全部」（`TaskItem` の `childProgress`。消した・アーカイブした子と記録は数えない）。夢の行は次の一歩と一緒に出すので題名の右には出さない
- やりたいこと（種類 `someday`）のリストは 2 段に分ける（`lib/somedayTier.ts`、#439）
  - 画面の名前は「人生で」と「近いうちに」（#524。英語 Lifetime / Soon）で、このあとは中の呼び名の「夢」「やりたい」で書く
  - 夢は一歩ずつ進める人生の目標（合格・就職・貯金・語学）や人生で一度はやりたいこと（スカイダイビング）、やりたいは日を決めればできること（旅行もここ）で、どちらにするかは利用者が決める
  - 分けるのは眺め方を変えるため
  - 夢が 1 件も無い（かなえた夢も無い）あいだは切り替えも夢ボードも出さず、やりたいの一覧だけ（#517）
  - 夢があれば上に切り替え「夢 n | やりたい n」（開いたときは夢があれば夢、無ければやりたい）
  - 追加欄から入れると開いている側に入る（夢ボードなら夢）
  - 入れるときは詳細のチップ「人生で」（ロケットの印）で夢にする・しないを選べる（`QuickAddPicks.dream`）
  - セクションは切り替えの下の絞り込み「# 海外」…（`todo/SomedayParts.tsx`。ナビのセクションと同じ `quickAddSectionId`。色はセクションの並び順で決め、データに持たせない）
  - 絞り込むと切り替えを消して夢とやりたいを上下に出し、入れるとそのセクションに入る
  - 夢はボード（`todo/DreamBoard.tsx`）: スマホ 2 列・広い画面ほど列を増やすタイル
  - セクションの色の薄い塗り＋縁（セクションの外は白地に灰色の縁）、題名、一歩があれば次の一歩と細い進み具合、セクション名
  - 押すと詳細、右クリック・長押しで行と同じメニュー。かなえた・段を移す・削除は詳細の … からもできる
  - 夢の一歩は一覧の行に出さない
  - かなえた夢はボードの下に「かなえた夢」として日付と ★ つきで残す
  - やりたいは棚: 一番上に「今週これどう？」（やりたいが 2 件以上のとき、ランダムに 1 件、↻ で替える、予定する）、その下に行（予定する付き、セクションで絞り込んでいなければセクション名を添える）
  - 下の「かなえた」の一覧はやりたいだけ
  - 夢だけを `somedayTier: 'dream'` で持ち、持たないものはやりたい（新しく入れたものもやりたい。一歩＝子は段を持たない。一歩を足しても自動では夢にしない）
  - 段の移動はメニューの「「人生で」へ移す」/「「近いうちに」へ移す」（下に段の説明、`MenuItem` の `detail`）
  - 夢の本体には「予定する」を出さない（一歩を予定にする）
  - 夢の一歩を予定にして To-Do になった行は元の夢を `dreamId` で覚え（`040`）、夢の進み具合・次の一歩に数える（次の一歩は予定にした済んでいない一歩を日付の早い順に先に、無ければ夢の下の並び順。予定にした一歩は済んでアーカイブしても数え、消したものは数えない）
  - その To-Do の行にはロケットの印と夢の名前を添える
  - 夢を消した・かなえた・やりたいへ移してもつながりは外さず、数えない・出さないだけ（1 つの操作で多くの行を書き直さない）
  - ほかのリストへ移す・予定にして To-Do になると段は外す
  - 前の版のデータは、いつかのリストの一歩を持つルートの行を夢にする（保存データの版 41・`034`）

## タイムゾーン

### タイムゾーン

- アプリのタイムゾーンは設定「日付と時刻」（既定は端末）。「今」「今日」・Google の予定・止め忘れタイマー・Web Push がそれに従う（`src/lib/timeZone.ts` の `zonedNow()` / `isAppToday()`）
- `src/components`・`src/hooks` の引数なしの `new Date()` は lint で止める（`.toISOString()`・`.getTime()` に続く瞬間の値は使える）。date-fns の `isToday`・`isPast`・`startOfToday` など端末の今日を見る関数はテスト以外で止める（`eslint.config.js`）
- 画面で「今」「今日」を使うときは時計の購読（`src/hooks/useAppClock.ts` の `useNow()` / `useNowMinutes()` / `useAppTodayKey()`）を読む
  - `useMemo` の中で今日・今を読むなら、その値を依存に入れる（入れないと日をまたいでも昨日の結果のまま。`src/hooks/memoReadsClock.test.ts` で止める）
  - 時計はアプリで 1 つ（`src/lib/appClock.ts`）で、分の境目と表に戻ったときに進む
  - 画面ごとにタイマーを回さない
  - 見ている日は今日の計画・カレンダー・習慣でそれぞれ持ち、ほかの画面とは共有しない（通知・ふりかえりから今日の計画を開くときは今日の計画の日だけを動かす）
  - 開いたまま日をまたぐと、今日を見ていた画面の見ている日は新しい今日に進む（`useFollowToday`）
- 予定・記録の時刻はアプリのタイムゾーンの壁時計（`yyyy-MM-dd` と `HH:mm`）。長さ・日の中の位置・日ごとの切り分けは端末の Date にせず、日の通し番号 × 1440 + 0 時からの分で数える（`src/lib/wallTime.ts`、`taskWallInterval`）。端末の夏時間が切り替わる日（23 時間・25 時間）も 09:00–10:00 は 9 時の位置で 60 分
- タスク・記録ごとのタイムゾーンを持てる（`src/lib/taskTimeZone.ts`）。列はアプリのタイムゾーンで持ち、`timeZoneAnchor` で同じ瞬間へ書き直す
- アプリのタイムゾーンを変えると、時刻のある予定・記録は同じ瞬間のままずれる（東京 19 時 → NY 6 時）。日付だけのタスクと習慣は動かない。書いたタイムゾーンが分からない古いものは、最初に開いたときのタイムゾーンで書いたとみなす
- タイムラインの時間バーに他のタイムゾーンを 2 つまで並べられる（`TimeGutter.tsx`）
- 他のタイムゾーンには名前を付けられる（設定の行の「名前（任意）」）。時間バーの見出しは名前、無ければ `GMT+9` の形。長い名前は切って出し、ヒントに名前とタイムゾーンの全体を出す。並びと名前は端末間で同期する（`user_extra_time_zones`、`src/lib/extraTimeZones.ts`）

### 週の開始日

- 週の開始日は設定「日付と時刻」で 土曜 / 日曜 / 月曜（既定は月曜、端末に保存・他のタブと共有、端末間では同期しない、`weekStartsOn`）。従うのはカレンダーの週・月表示、週の見出しの範囲、日付ピッカー、習慣の月のカレンダーの並び（`src/lib/weekStart.ts`）。習慣の「週に◯回」・習慣の画面の週・週のふりかえり・統計の週と月の集計・クイック追加の「今週中」「週末」・毎週の繰り返しは月曜はじまりのまま

### よく入れる予定・毎週の予定

- よく入れる予定（バイトのシフトなど）は月表示の見出しの「よく入れる予定 ▾」で登録する（名前・始まり〜終わり・ラベル。日はまたげない、終わり 0:00 はその日の終わりまで、30 件まで）
  - 1 つ選ぶと格子の上に帯が出て、日を押すとその日に同じ予定（`kind: 'event'`、未分類）が入り、もう一度押すと外れる（その間に入れたものは消し、前からあったものはゴミ箱へ）
  - 続けて押した分は 1 回の取り消しで戻る（`asUndoSession`）
  - 「完了」・Esc・ほかの表示へ移ると抜ける
  - 登録は端末間で同期する（`user_event_templates`、`src/lib/eventTemplates.ts`）
- 予定は詳細の「繰り返し」で毎週にできる（曜日・終わりの日・祝日は入れない。To-Do の繰り返しとは別で、完了で次を作らない）
  - 回は終わりの日（既定は学期の終わり、無ければ 15 週、1 年まで）までの分を前もってふつうの予定の行として作り、同じ印（`series`、`tasks.event_series`）を付ける（`src/lib/eventSeries.ts`）
  - 曜日・終わりの日・祝日を変えるとその回から後を作り直す（当てはまらない回はゴミ箱へ入れて繰り返しの印を外し、「N 回分を削除しました · 元に戻す」を出す。1 回だけ消した回の日は作り直さない）
  - その回より前に回があれば、その回から後は別の繰り返しになり、前の回の終わりの日は前の回の最後の日になる
  - 「繰り返さない」に戻すと、その回より後の回をゴミ箱へ入れる（件数を出して確かめる）
- 毎週の予定のカード・詳細には「変える範囲」（この予定のみ / これ以降すべて / すべて、既定はこの予定のみ）を出す（ほかに回があるときだけ）
  - 選んだ範囲の回に、名前・メモ・場所・時刻・色・通知・リスト・タグ・タイムゾーンを写す
  - 日付は回ごと
  - 閉じると「この予定のみ」に戻る
  - ドラッグ・右クリックのメニューで動かすのはその回だけ
  - 削除（カードのごみ箱・Delete キー・右クリック・詳細）は範囲を聞くダイアログを出し、選んだ範囲の回をゴミ箱へ（取り消しで戻る）
  - To-Do にした回は繰り返しから外れる（毎週の回には To-Do / 予定の切り替えを出さない）

### 追加機能・学校

- 追加機能は「学校」（時間割・授業の欠席の一覧・予定カードの欠席の数）と「引き落とし・期限」
  - 追加機能の画面のカードはアイコン・名前・ⓘ（押すと説明のポップアップ）・スイッチで、オンのカードは押すとその機能のページへ進む（› を出す。「‹ 追加機能」で戻る）
  - 学校のページは時間割と授業の欠席を 1 ページに並べる
  - 学校は決めていなければ毎週の予定がある人だけオン
  - 前の版の時間割のオン・オフは学校に移し、どちらかがオンなら学校はオン（`src/lib/addons.ts`）
- 時間割は週・3 日表示の見出しの「時間割」（ダイアログ）と追加機能「学校」のページから開く
  - 曜日（月〜土）× 時限のマスで、マスはボタン（「月曜 2限 空き」「月曜 2限 経済学入門」と読む）。空きのマスには薄い ＋ をいつも出す
  - 押すと授業名（Canvas・Moodle の科目名を候補に出す。選ぶと予定のカードにその科目の課題が出る）とラベルを入れ、学期の間・今日から後のその曜日の毎週の予定ができる（1 回の取り消しで全部戻る）
  - 入っているマスは名前・ラベルを直す・消す（今日から後の回だけ。過ぎた回は残す。確認なしで「「名前」を N 回分削除しました · 元に戻す」）
  - 上で学期を選び（学期が無ければ「学期を追加」から）、マスの上のたたんだ「時限と祝日」を開くと、時限（既定 5 つ、12 まで、使える形のときだけ保存。学期をまたいで同じ）・祝日は授業を入れない（既定は入れる）を決める
  - 時限を変えても入れた授業は動かない
  - マスに出すのは始まりの時刻がその時限に入る授業
  - 時限・祝日は端末間で同期する（`user_timetable`、`src/lib/timetable.ts`）
- 学校は学期を箱にして、その中に授業を置く（`src/lib/schoolTerms.ts`）。学期は名前・始まり・終わりで、いくつでも持て（24 まで）、重ならない。足すときの案は最後の学期の次の前期（4/1〜7/31）か後期（10/1〜1/31）。学校のページと時間割のダイアログで最初に見せるのは、今日の学期 → これから始まるいちばん近い学期 → いちばん最近の学期。学期を消すと、その学期の欠席・休める回数・追加した授業も消える（時間割の予定は残る。確認なしで「元に戻す」付き）
- 学期の授業は、その学期の時間割の授業・「授業を追加」で入れた授業・学期の間に締切のある Canvas・Moodle の科目（時間割・追加した授業につながっていない、一覧から外していないもの）を、名前（`courseKey`）で 1 つにまとめたもの
  - 並びはあと何回休めるかが少ない順（決めていない授業は後ろ）、同じなら名前順
  - 「授業を追加」の候補は、学期の間の Google カレンダーの毎週の予定と、一覧に無い Canvas・Moodle の科目（Google の予定は自動では入れない）
- 授業は欠席と課題を持つ。欠席はその日の学期に数え、学期の無い日は付けない。休める回数は授業ごとで、決めていなければ時間割の授業は学期の回数の 1/3、ほかは決めない（回数だけ出す）。課題は授業につながる科目の未完了の課題（予定のカードと同じつながり `courseLinks`。授業のページで科目を選び直せる）
- 授業のページ（学校の一覧で授業を押す。「‹ 学校」で戻る）は、時間割のコマ・欠席（今日欠席・休める回数・休んだ日）・課題。追加した授業は名前を直せる。追加した授業と Canvas・Moodle の科目は「一覧から外す」で外せ（欠席・休める回数も消える。科目は外した印が残り、足し直すと消える）、時間割の授業は時間割のマスから消す
- 予定のカードの欠席の数は、学校がオンで、その日の学期があり、時間割の授業か学期の授業と同じ名前の予定（Google カレンダーの予定も）のときだけ出す
- 学期と授業は追加機能の設定（`user_addons.addons.school`）に持ち、端末間で同期する
  - 両方の端末で変えたときは学期は id ごと、名前・期間は項目ごと、欠席は授業ごとの日付の集合、休める回数は授業ごと、追加した授業・外した科目は名前の集合で合わせる
  - まだ無ければ、時間割の設定の学期・欠席・休める回数と欠席の一覧の授業（`absenceCourses`）から 1 つめの学期を作って見せる（学期を決めていなければ欠席の日の範囲。どちらも無ければ学期なし）
  - 書くのは何かを変えたとき

## 言葉

- 呼び名をそろえる: **締切**（dueDate。To-Do に「期限」は使わない。過ぎたものは「締切切れ」）／**実行日**（scheduledDate。やる日。「予定日」は使わない）／**予定**（時刻のある予定）／**記録**（「計測」「ログ」は使わない）／**ラベル**（色に付けた名前）と **タグ**（To-Do の自由な札）は別物／**達成**（習慣）・**完了**（タスク）／**バックアップ**（「控え」は使わない）／**取り込む**（バックアップ）／**外す**・**すべて**・**ない**
- **予定 N 件中 M 件**（今日の計画の見出し・週のふりかえりの「計画どおり実行」と日ごとの棒・朝のまとめの「昨日」・夜のまとめの通知）: 時間に置いた To-Do（その日から別の日へ移したものも）と時間を決めた習慣の枠（週に◯回の習慣はやった日だけ）のうち、記録と組になった・✓ で終えた数
  - 予定（授業・バイト）は数えない（その時間の記録は予定外にしない）
  - 今日はまだ終わっていないものを入れない
  - アプリと Edge Function で同じもの（`supabase/functions/_shared/dayResult.ts` の `countDayResult`、習慣の判定は `_shared/habitTiming.ts`）
  - To-Do の完了数は「完了 M/N」と書いて「予定」と呼ばない
  - 時間に置いた To-Do と時間未定の見積もりの合計は「置いた ◯時間」
- Google のサービス名は「Google カレンダー」。切断は「接続を解除」
- 「期限」は有効期限（パスポート・無料体験・ログインのリンク・トークン）と、追加機能「引き落とし・期限」の日だけ。To-Do の締切とは別のもの
- 「目標」は届いたら達成になる量（習慣の「1 回の目標」）。「目安」は届かなくても何も変わらない記録の目当て（ラベルの「週に◯時間」）。計画の空きのもとは「1 日に使える時間」と呼び、目安・目標とは言わない
- 追加・編集のボタンと文は「追加」「編集」（「足す」「直す」は使わない）
- 「〜ましょう」と促さない。事実と、そうすると何が起きるかを書く
- 表記: 「〜」の前後に空白なし、「＋」の後に空白なし、三点リーダーは「…」、「か月」、括弧は全角、数字の前後は空白（「直近 7 日」）、見出しの件数に「件」
- 英語は件数のある文に単数形（`_one`）を置く。実行日は "Do date"
- 利用者に見える文に開発者向けの言葉（環境変数・ビルド・ID の重複など直せないもの）を出さない

## 表示

### 全体

- 1 日の区切りは 0 時。今日の計画・To‑Do の今日/締切・習慣・統計・完了した日・クイック追加の「明日」がそれに従う。前の日に終わらなかった予定は遅れとして今日のやり残し（`getDayPlan().carryOver`）に繰り越す。タイムラインも 0 時で日が切り替わり、1 日表示は 0〜24 時だけを出す
- 一括選択のチェックはホバーで出す。タッチでは行の長押しで浮かせて選択に入れるので、iPad でも常時は出さない（全行にチェックが並ぶとごちゃつく）
- 並べ替えのつまみ ⠿ は PC（細かいポインタ）だけ。タッチ主体の端末では出さず、行の長押しから運ぶ（`useRowGrip`）
- 設定の「締切の前」は、いつ届くか（前日 20:00・時刻があれば 3 時間前）を行の名前に書く（説明の行は足さない）
- ダークの塗りのボタンは白にせず一段落とす（`--color-accent-500: #bdc1c6`）。暗い画面で一番まぶしい所を作らない
- 開いている画面は URL（`?view=` か `?list=`、絞り込みは `&tag=`・`&color=`）と履歴に載せ、ブラウザ・Android の「戻る」で前の画面に戻る（`lib/urlHistory.ts`・`lib/viewUrl.ts`）
  - 起動時は URL の画面を開く
  - 画面が替わるたびに履歴を積み（`pushState`）、戻る・進む（`popstate`）で URL の画面を開く
  - 最初の履歴・戻る / 進むで開いた画面・リストの削除や同期でリストが替わったときは積まずに置き換える（`replaceState`）。置き換えるときはほかのクエリ（OAuth の `code`・`state`）とハッシュ（ログイン）を残す
  - 戻った先のリストが無ければ「すべて」
  - モーダル・ドロワー・検索語は URL に載せない
- 常時出す説明文は置かない。残すのは iPhone/ブラウザの追加手順、アカウント削除の警告、エラー・確認、ホバーのツールチップ

### はじめて使う人

- はじめて使う人には、今日の画面（今日を見ているとき）で説明の段落を出さず、触って覚えてもらう
  - 追加欄の下に進み具合の 1 行（点 3 つ＋いまのステップの名前＋×。やることを 1 つ入れる・時間に置く・▶ で記録する。名前は PC とタッチで言い方を変える）
  - 済んだステップはデータから自動で点が埋まる（To-Do がある・時間帯のある To-Do がある・記録があるかタイマーが動いている）
  - 3 つ終わると「できました」を 4 秒出して消え、× でも消え、二度と出ない（`onboardingDone`、端末に保存。`PlannerOnboarding`）
  - × で閉じたときは「案内を閉じました・元に戻す」のお知らせを出し、元に戻す（⌘Z も）で案内が戻る（`onboardingDone`・`onboardingFinishedOn` は取り消しの履歴で戻す設定に入れてある）
  - 版 39 より前にタスク・習慣のあった人、バックアップを取り込んだ人、この端末の初めての同期でアカウントにデータが届いた人には出さない
  - 案内の間でまだ何も無い日は追加欄が入口（`PlannerAddInput` の `guide`）: PC は開いたときに欄にカーソルを置き（スマホは置かない）、薄い文字の例を 2.6 秒ごとに入れ替え（バイト 17時-22時・レポート 明日まで・ES 金曜まで・ゼミの発表準備 2時間）、欄が空の間は下に例のボタンを 2 つ（時間の決まった「バイト 17時-22時」と締切の「レポート 明日まで」、押すと欄に入り読み取りのチップが見える）
  - 1 件入れたら普段の欄に戻る
  - 案内のいまのステップが ③ の間は、PC の今日の行の ▶ を乗せなくても出す（`useOnboardingStep`・`RowActionButton` の `pinned`）
  - 案内の間に時刻つきで足すと、PC は枠の写しが追加欄からタイムラインのその時間へ形を変えながら移り（`flyIntoTimeline`）、スマホは「タイムライン」のタブが弾む（`nudgeTimelineTab`）
  - どちらも動きを減らす設定では出さない
  - 案内の間で ② が済んでいないとき、PC の今日の計画のタイムラインには、時間の決まっていない最初の To-Do 用に今より後の最初の空きへ点線の「ここに置く」を出し、押すとそこに置く（長さは見積もり、無ければ既定の予定の長さ。ドラッグ・作成中は出さない。`OnboardingPlaceSlot`）
  - 案内が出ている間と、案内を終えた日（`onboardingFinishedOn`、端末に保存）は睡眠の行を出さない（最初に目に入るものを、やることの追加にする。最初の成功の場面に新しいものを重ねない）
  - 案内の無い人の何も置いていない日は、追加欄に「レポート 明日まで」を薄く出す
  - カレンダーは、タスクも Google の予定も 1 つもない間だけ週・3 日表示の上に「空いている時間を押すと…」を 1 行出す
  - 設定のラベルの「30 日間 未使用」は、まだ記録が 1 件もないうちは出さない
- 3 ステップをやり終えた人（× で閉じた人・案内の出ない人は除く、`onboardingCompleted`）には、次の日から（終えた日は出さない）案内のあった場所に 1 回だけ誘いのカードを出す（`OnboardingNudges`・`lib/onboardingNudge.ts`）
  - iPhone / iPad の Safari でホーム画面に未追加なら「ホーム画面に追加すると通知が届きます」と「共有ボタン →「ホーム画面に追加」」
  - × で閉じたら二度と出ない（`installNudgeDismissed`、端末に保存）
  - ほかの環境・追加済みでは出さない
  - それ以外（iPhone はホーム画面から開いたとき。ホーム画面のアプリは保存先が別なので、そこで案内が済んでいれば出す）は「予定が終わったら、通知で「予定どおり / 記録する」を聞きます」と「通知をオンにする」（許可を聞き、許されたら予定のあとの確認をオン）
  - 通知が使えない・断られている・もうオンなら出さない
  - 押す・× のどちらでも、下の通知の 1 行（`reminderPromptDismissed`）ともども二度と出さない
  - カードを出している間は下の通知の 1 行を出さない

### To-Do の行・締切

- To-Do の行の締切は「まで」を付けて実行日（カレンダーの印）と文字で分ける。過ぎたら「◯日遅れ」、2〜3 日後は「あと ◯ 日」（明日と同じ色）。色だけに頼らない（2 型色覚で赤とオレンジが見分けられない）
- 締切を外すと締切の時刻と繰り返しも外し、実行日を外すと時間帯も外す（`taskHelpers.ts`）
- 予定（`kind: 'event'`）は完了が無い（`toggleTask` は何もしない）。To-Do の一覧・時間未定のタスク・今日の計画の To-Do・やり残し・完了の数・統計には入れない
  - To-Do と予定は詳細の切り替えで変える（サブタスク・子のある行・毎週の予定の回には出さない）。予定にすると締切・繰り返し・完了・優先度を外す
- 優先度の色は 高＝赤・中＝黄・低＝青（`priorityColor.ts`）。締切切れとは「◯日遅れ」の文字で分ける。やり残しの見出しも、To-Do の行の過ぎた実行日も責める色にしない（灰色）
- To-Do は続けて持ち越した日数（`carriedDays`、`lib/carryDays.ts`）を持つ
  - 今日かそれより前に置いて終わっていない To-Do を後ろの日へ回すと、やらずに過ぎた日の分だけ足す（明日へ回す・翌日へ回す・やり残しを今日へ・カレンダーで後ろの日へ動かす。今日 → 明日で +1、3 日前 → 今日で +3）
  - 前の日に置いたまま（やり残し）の日数は見る日までの分を足して数える（`carriedDaysOn`）
  - 完了・実行日を外す・いつか / チェックリストのリストへ移すと 0（完了を戻しても 0 のまま）
  - 先の日どうしの付け替え・前の日へ戻すのは数えない
  - 今日の計画は今日を見ているとき、やり残し・今日やる行で 2 日以上なら右に灰色で「3日目」（1 日は出さない。締切の過ぎた行は「2日遅れ」があるので出さない）
  - 週のふりかえりは今の週・月だけ、2 日以上のタスクを日数の多い順に 3 件「持ち越しが続いているタスク」（無ければ出さない）
  - 押すと To-Do 一覧と同じタスクのメニュー（詳細を開いてサブタスクに分ける・リストへ移動でいつかへ・削除）
- サブタスクのうち実行日か締切のあるもの（企業の下の ES 締切・面接など）は、今日の計画では 1 件の To-Do として扱う（期限切れ・やり残し・今日やる・締切間近・候補・完了の数、置いた時間。`isDayPlanTask`）。行には題名の下に親の名前を小さく灰色で出す。日付の無いサブタスクは親の中の手順のまま出さない。締切の通知（予定の前・締切の前・朝のまとめの締切）はルートのタスクだけのまま
- 子の行が見えない所の親の行（カレンダーの横の To-Do。上の段だけを並べる）には、まだ終わっていない子（直下）のうちいちばん近い締切を「ES 10/15 (木)まで」の形で締切の色で出す（`nextChildDue`・`useChildDue`・`ChildDueChip`。同じ日は時刻つきが先。親の締切のほうが先か同じなら出さない。子が全部済めば出さない）。子の行がすぐ下に見える To-Do 一覧と、締切のある子が自分の行で出る今日の計画では出さない

### 今日の計画

- 今日の計画の今日やる行の締切は、過ぎた締切と今日の締切だけ出す（決めたあとでは先の締切は何も変えない）。ただし、その画面の追加欄で足したばかりの行は先の締切も出す（書いた「明日まで」が伝わったと分かるように。ほかの画面へ移ると戻る）
- 今日の計画の「締切が近い To-Do」は、先の日に置いた To-Do のうち締切が見ている日〜3 日後のもの（締切が今日なら先の日に置いていても入る。`getDayPlan().dueSoon`）
  - 明日までの締切があれば最初から開く（開け閉めを選んだらそれに従う）
  - 締切間近の下の候補（締切が先・日付なし・先の日に置いたもの）は 10 件ずつ「さらに表示（残り N 件）」で足す（最後の行で ↓ でも足す。スクロールでは足さず、下の習慣・完了・気分の記号に届くようにする）
- 締切切れは今日のリストの先頭に赤い日付つきで出す（`getDayPlan().overdue`）。スマホ幅は 2 行まで出し、残りは「他 N 件」で開く（PC は全部）
- 今日の計画のキー操作（↑↓・Space など）の対象は、出ている行を上から（締切切れ → やり残し → 今日やる → 候補 → 完了）。やり残し・候補・完了は欄を開いているときだけ
- スマホ幅の今日の計画は、今日を見ているとき、今日やる行の一番上に始まっていて終わっていない 1 件か次の 1 件を「今」「次」を付けて 1 行出す（`nowOrNextPlan`）
  - 対象は時間を決めた To-Do・予定（授業・バイト）・時刻つきの Google の予定で、今のものが先、無ければ早く始まるもの（同じ時刻なら To-Do）
  - To-Do ならその間は下の時間を決めた行から外し、↑↓ の並びでもここが先頭
  - 予定は ✓ が無く、押すとタイムラインと同じ予定のカード
  - PC は横のタイムラインにあるので出さず、時間を決めた行もそのまま
- 今日の計画の見出しの右に「置いた 3時間 / 空き 5時間」を小さく灰色で出す（置いた時間が 0 なら出さない）。超えた日は「（超過）」を付ける。出すのは計画しているとき（今日の夜のまとめの時刻より前と、先の日）だけ
- 今日の計画の見出しには記録の合計・記録の無い時間の合計・その日の結果（予定 N 件中 M 件・予定外）を出さない（記入漏れ・重なりで意味がぶれる。結果は週のふりかえりと通知で見る）。過ぎた日と、今日の夜のまとめの時刻（無ければ 17 時）から（`showsDayResult`）は、記録の帯とラベル別の時間を出す。今日の昼・先の日には出さない
- スマホの今日の計画は、過ぎた日と今日の夜のまとめの時刻から（`showsDayResult` と同じ）は「タイムライン」の面から開き、それ以外は「やること」から（ふりかえりの棒・夜のまとめの通知から開いたときも同じ。夜のまとめの通知はいつもタイムライン）
  - タブで選んだ面は、アプリの今日のうちはどの日を開いても従う
  - 見ている間に夜のまとめの時刻を過ぎても替えず、見る日を変えた・アプリに戻ったときに決め直す（`lib/plannerPane.ts`）
- 今日の計画の追加欄で足した行は、その日の時間未定の行の最後に入る（欄は行の下にあるので、足した行が欄のすぐ上に見える）
- 今日の計画の記録の帯の下にラベル別の時間（重なった記録の時間は 2 回数えず、あとから始まった記録のラベルに入れる。`minutesByRecordLabel`）。PC はすべて、スマホは多い順に 2 件を 1 行で（残りは「ほか」）、帯の右の › を押すとすべて開く

### 空き・見積もり

- その日の空きと置いた To-Do は週表示の見出しと今日の計画の見出しで同じ計算（`dayLoad.ts` の `dayLoad`、`useDayLoads`）
  - 空き = 設定「計画 › 1 日に使える時間」−（予定と時刻つきの Google の予定でふさがっている時間。重なりは 1 回、To-Do・記録・習慣の時間枠・終日の予定は入れない）、0 より小さくしない
  - 1 日に使える時間は 4〜10・12 時間から選ぶ（既定 8 時間、`dailyCapacityMinutes`）
  - 置いた時間は、その日に置いた To-Do（終日の行・時刻つき。完了も含む）の、時刻つきならその長さ、時刻なしは見積もり（見積もりの無いものは数えない）
  - 予定・いつか / チェックリストのリストは入れない（サブタスクはその日に置いたものだけ入れる）
  - 置いた時間が空きを超えたら締切の色にし、色のほかに文字でも分かるようにする
  - 空き・超過は今日から先の日だけ出す
- 週表示の各日の見出し（日付の下）に、その日の空きを小さく灰色で出す（「空き 3h」）。超えた日は「空き 3h / 5h」と置いた時間を足す（スマホの週の帯は「3h/5h」）
- 今日やる候補の締切の日の見出し（締切順のときの 1 週間以内の日ごと）は、その締切までの見積もりが空きに入りきらないときだけ、見出しの右に締切の色で「入りきらない」を出す（数字はホバー・読み上げで「見積もり 6時間 / 空き 3時間」）
  - 見積もりはその見出しまで（前の締切の見出しも含む）の候補の見積もりの合計（見積もりの無い行は数えない）、空きは見ている日から締切の前日まで（今日・明日までの締切は見ている日だけ）の各日の空き（週の見出しと同じ `freeMinutesOfDay`）の合計（`dueFits`、`dayLoad.ts`）
  - 締切順以外の並び順（既定の優先度順など）は見出しが無いので、見出しは足さず、入りきらない締切を持つ候補の行の締切の文字を締切の赤にする（数字はホバー・読み上げ）
  - 見積もり・空きの数え方は締切順と同じ（締切順に並べたときのまとまりで数える）
  - 入りきるとき・見積もりが無いときは何も足さない
  - 過ぎた日を見ているときは出さない
  - タイムラインには足さず、勝手に置くこともしない
- 長さを決めずに作る予定（空き時間のクリック・長押し、タスクをタイムラインに置く、「時間を決める」の初期値、時刻だけのクイック入力、予定・習慣の終わりの時刻ピッカー）は設定「計画 › 既定の予定の長さ」（15 / 30 / 45 / 60 / 90 / 120 分、既定 60 分、端末に保存、`defaultBlockMinutes`）。記録の時刻ピッカーは 1 時間のまま
- To-Do は見積もり（`estimateMinutes`、詳細の「見積もり」、クイック入力で時刻なしの長さ「ES 30m」「レポート 2時間」）を持てる。タイムラインに置く長さは 時間帯 → 見積もり → 既定の予定の長さ の順（落とす前の影も同じ長さ）。「時間を決める」の長さの初期値も見積もり。予定（完了の丸なし）には付けない
- 見積もりと実際に記録した時間（`estimateActual.ts`）: To-Do の記録は ▶ で始めた記録の元の To-Do（`sourceTaskId`）で結ぶ
  - 元を覚えていない記録は、題名が完全に同じ（前後の空白は無視）・その題名の To-Do が 1 つだけ・記録の開始日が To-Do を作った日〜完了した日（未完了は今日）・習慣の記録でない、を全部満たすときだけ結ぶ（似た題名・繰り返しの回は結ばない）
  - 結び付いた記録は日・週をまたいでも全部足す（睡眠・削除・子の記録は入れない）
  - 見せるのは決めた後だけ: 週のふりかえりの「見積もりと記録」（その週に完了した、見積もりと記録のある To-Do を見積もりを超えた分の大きい順に 5 件。無い週は出さない。点線の枠が見積もり、塗りがいちばん長い記録のラベルの色）と、完了した To-Do の詳細の見積もりの下の「記録した時間」
  - 今日の計画の行・タイムラインには出さない
- 見積もりのクセ（`estimateBias`・`EstimateBiasHint`）: 見積もりと結び付いた記録が両方ある完了した To-Do の「記録 ÷ 見積もり」の中央値
  - その To-Do のラベル（ラベルなしはラベルなし同士）で 5 件以上ならその倍率、無ければ全体、全体でも 5 件未満なら出さない
  - 0.8〜1.2 は出さない
  - いつか・チェックリストは数えない
  - 詳細の見積もりを選んだ直後と「時間を決める」を初めの長さのまま開いている間に「いつも見積もりの 1.5 倍かかっています · 1時間30分にする」（ラベルのある To-Do は「このラベルはいつも…」）
  - 押すとその長さ（15 分単位、15 分より短くしない）にし、勝手には直さない
  - 直しても同じ長さなら出さない

### カレンダー

- カレンダーは置いた日（実行日 → 締切日）の 1 日に出すうえ、実行日が別の日の未完了は締切の日にも →| の印を出す（`dueMarkDayKey`。週・3 日は終日の行、スケジュール・日のパネルはその日の行の後ろに 1 件ずつ。月のマスは 1 件なら題名、2 件以上は 1 行にまとめて件数で、押すとマスを広げて 1 件ずつ）。締切の印は終日の行・月のマスの件数の上限に数えず、たたんでも「他 N 件」に入れずに出す。どの表示でも印を押すとその To‑Do のカード（`calendar/TaskDueMark`）
- 月のマスには Google の終日の予定も出す（週の終日の行と同じ薄い塗りの帯で、時刻つきの行より先）。予定と To‑Do で 3 行を超えるマスは「他 N 件」で、押すとマスを広げて全部出し、「たたむ」で戻す（週の終日の行の「他 N 件」と同じ）。スマホ幅は「他 N 件」・締切の行もマスと同じくその日の 1 日表示を開く
- カレンダーの予定の見せ方はどの表示（タイムライン・終日の行・月のマス・スケジュール・日のパネル・カード）でも同じ（`lib/planVisual`）
  - 時間が過ぎた予定（完了・未完了とも。終日・時刻なしはその日の終わりを過ぎたら）は灰色。Google の予定も同じ条件
  - 完了した To‑Do は終えた日に、灰色と塗りの ✓ で出す。取り消し線は引かない（日のパネルは「完了 N 件」に畳む）
  - ラベル（色）の無いこれからの予定は塗らずに灰の縁だけ（`gc-plan-none`、小さな丸は `gc-dot-none`）。灰色の塗りは時間が過ぎた予定だけ
- カレンダーの行の右クリック・長押しのメニューは種類で決まり、表示で変えない（`openCalendarItemMenu`）: 予定は予定のメニュー（`TaskEventMenu`）、To‑Do は時刻の有無によらず To‑Do のメニュー、Google の予定は Google の予定のメニュー（月・終日の行・スケジュール・日のパネル）、記録は日のパネルの記録の行で記録のメニュー（睡眠はメニューなし）。タイムラインは下の `brief`
- 完了したタスクは、置いた日・締切ではなく完了した日に出す（`completionDayKey`。今日画面・日のパネル・完了済み）。カレンダーも同じ（`calendarDayKey`）: 時刻つきの予定は、予定の日（日をまたぐならその範囲）に終えたなら予定の時間帯のまま、別の日に終えたら終えた日の終日の行・月のマスに時刻を付けずに出す（`keepsTimeSlot`）。予定と記録の比較・予定の分数は予定なので置いた日で数える
- 過ぎた日のタイムラインに、移した時刻つきの予定を元の時間に点線の枠（題名と「→10/5」、押すと To-Do のカード）で出す。今日・これからの日には出さない。1 日表示の予定の列の見出しは「予定」だけ（数は横の To-Do の一覧で見る）
- カレンダーの表示: PC は 月 / 週 / スケジュール（‹ › は PC だけ）、スマホ（768px 未満）は スケジュール / 日 / 3日 / 月（見出しのメニュー）。PC で 3日 を残していたら週で出す。スマホの見出しは 1 行で、左から「10月 ▾」（今年でなければ年も。押すとミニ月が下に開き中身を押し下げる）・Google の接続の点・今日・表示・よく入れる予定（月）か時間割（日・3日）・時間未定（`CalendarMobileHeader`）
- スマホの「日」は 1 日（予定｜記録の 2 列。週と同じく #403 の左右半分と #409 の全幅が効く）、「3日」は予定の列だけ。月のマス・3日 の日付・スケジュールの日付を押すと、その日の「日」を開く
- スマホのカレンダーの横スワイプ（`useSwipeNav`。60px か速く払えば 20px で送る。2 本指・ドラッグ中・持ち上げ中は無視）: タイムラインは表示の日数（日 は 1 日、3日 は 3 日）、日 の曜日の帯は同じ曜日のまま 1 週、月は 1 か月。スケジュールは送らない
- タッチの長押し（450ms、8px 動いたら取り消す。15ms 震わせる）は右クリックと同じメニュー（`useTouchContextMenu`。月のマス・終日の行・スケジュール・日のパネルの行の `data-touch-menu`、To‑Do の行の `data-task-row`）
  - タイムラインの予定・To‑Do は右クリック・長押しで「完了にする / 未完了に戻す」（To‑Do だけ）・「コピー」だけの短いメニュー（`TaskEventMenu` の `brief`）
  - 書き込める Google の予定は「コピー」だけ（`GoogleEventMenu` の `brief`）
  - 記録・書き込めない Google の予定にはメニューを出さず、長押しは押したときと同じカードを開く
  - 習慣の枠は右クリック・長押しで習慣のメニュー
- タイムラインのタッチ（`useTimelineDrag`）: 予定を押すと小さなカード
  - 長押し（450ms）で持ち上げ、そのまま動かすと移動、下の端（20px か高さの 1/3 の小さいほう）からなら長さを変える
  - 持ち上げる前に指を動かすとスクロール
  - 持ち上げて動かさずに離すとメニュー
  - 持ち上げたまま上下の端に寄せるとスクロールし、その間は縦スクロールを止める
  - 空き時間を押すとその 30 分の頭から既定の長さ（設定 `defaultBlockMinutes`、既定 60 分）の作成カード
  - 長押しはその 15 分の頭から既定の長さの範囲を出し、指で終わりを動かして離すと作成カード
  - 予定と記録のどちらを作るかは押した列で決まる（未来は予定だけ）
- PC のタイムラインも空き時間をクリックするとその 30 分の頭から既定の長さ（`defaultBlockMinutes`）、ドラッグするとその範囲で作成カード（`QuickCreatePopover`）。外を押す・Esc は作らずに閉じる
  - 予定の列では題名の欄の下に、枠に入る To-Do を 1 件だけ「◯◯（45分・締切 明日）を置く」で出し、押すと枠の始まりから見積もりの長さで置く（`pickTodoForSlot`、`lib/slotFitTodo.ts`）
  - 出すのは見積もりが枠の長さ以内の、未完了で時刻の無い To-Do。サブタスク・いつか / チェックリストのリスト・予定・記録・先の日に置いたものは出さない
  - 選ぶ順は 締切の近い順（締切なしは後ろ）→ その日に置いた行 → 並び順
  - 題名を書き始めたら消す。記録の列・合うものが無いときは出さない
  - 予定の作成先はリストの欄で選ぶ。Google につないで書き込みを許可しているときは「Google カレンダー」も並び、選ぶと Google の予定として作る。リストを選んだ予定はアプリの中だけに置き、Google には送らない
  - 予定の題名を打つと、同じ名前の一番新しい予定（日付→開始→作った時刻）から作成先を先に選ぶ（`inferEventDestination`、`lib/eventDestination.ts`）: アプリの予定（ゴミ箱は除く）ならその予定のリスト（選べないリストなら今のリスト）、Google の予定（アプリから送った予定・やらなかった予定は除く）なら「Google カレンダー」。同じ日時ならアプリ
  - 名前は全角半角・大文字小文字・空白の違いだけ同じに数え、部分一致はしない（`googleSkipKey`）。送らない名前（`addons.googleSkip`）はアプリだけ
  - 自分で作成先を選び直したら、その名前の間は名前から変えない。名前から分からないときは前回選んだ作成先（端末に保存）
- 週・日のタイムライン（今日の計画とカレンダー）は予定を左半分、記録を右半分に分ける（`layoutPlanAndLog` の `fixedLanes`、`lib/overlapLayout.ts`）。3 日表示は記録を出さないので予定が全幅
  - 時間が重なるものは、1 日表示は等幅で横に並べ（`columns`）、週表示は少しずつ右へずらして重ねる（`cascade`。短いものほど上、カーソルを乗せたものが手前）
  - カレンダー（今日の計画の 1 日表示は除く）は、記録を置けない未来の時間の予定を全幅で出す
  - カレンダー（今日の計画の 1 日表示は除く）は、予定どおりの記録（`matchPlanAndActualForDate` の `matched`）がある予定を出さず、その記録を全幅で出す（重なる予定があれば右半分）
- スケジュール（`CalendarScheduleView`）は選んだ日から先の予定・To‑Do・Google の予定を日付ごとに並べる（何も無い日は出さない。祝日は出す。月が変わる所に月の見出し。30 日ずつ「さらに表示」。終えた To‑Do は終えた日に灰色で出す）。予定・Google の予定は色のカード（題名と時刻か終日）、To‑Do は `TaskItem`（`dayKey`・`calendarState`）、締切の印はその日の後ろ
- カレンダーの「時間未定のタスク」は押し込み表示（`aria-pressed`）。中は時刻の無い To‑Do（いつか・チェックリストは入れない）を締切の近い順に並べ、To‑Do ナビと同じラベル（色の丸と名前）と「ラベルなし」のチップで絞る（ラベルが 1 つも無ければチップの行を出さない。`CalendarTaskDock`）。下に開く面は 1 つずつ: 開いている間は月の下の日のパネル（md〜lg）を畳み、スマホ幅では未接続の案内も畳む
- カレンダーのタスクはどこでもその場で ✓（`timeline/CalendarCheck`）: 月のマス・終日の行はチップの左、時間ブロックは右上。完了済みは塗りの ✓ で、押すと戻せる。時刻のあるタスクも ✓ は完了だけで、記録は足さない（予定ブロックが時間を表している）。To‑Do の一覧・今日・日のパネル・時間未定のタスク・Space / ⌘Enter も同じ
- タイムライン（今日の計画・週・3 日・日）の予定のブロックの ✓ の意味は「終わった」の 1 つ（`SlotCheck`）。済んだものは右上の塗りの ✓ だけで見せ、題名に ✓ は付けない。灰色は時間が過ぎた予定（完了・未完了とも）。記録のブロックには ✓ を出さない
  - To‑Do: いつも出す。押すと完了
  - 予定（To-Do でない予定）・Google の予定: 始まってから出す。押すとその時間の記録を作る（ラベルは予定のラベル、Google の予定はその色）。同じ題名で予定の時間に重なる記録があれば ✓ 済みで、もう一度押すとその記録を外す（`planRecordOn`）。日をまたぐアプリの予定・やらなかった Google の予定には出さない
  - 習慣の枠: 始まってから出す。押すと予定どおり達成、もう一度押すと取り消し
  - 終わる前に押したら、記録は予定の開始から今まで（`checkRecordTimes`。習慣は今日の計画の習慣の行・カードの ✓ も同じ）。過ぎた日・終わった後は予定どおりの時間
- カレンダーで予定・To‑Do・Google の予定・締切の印を押すと、どの表示（月・週・3 日・1 日・スケジュール・日のパネル。日のパネルは記録の行も）でも横に小さなカード（Google の予定は `GoogleEventPopover`、ほかは `EventPopover`。スマホ幅は下からのシート。`useCalendarCards`・`calendar/CalendarCards`）。カードは画面に 1 枚で、月と日のパネルのように表示が並んでも、開くとほかのカードを閉じる
  - カードの右上の × はどのカード（予定・Google の予定・作成・習慣の枠・習慣の段のその日の一覧）にもあり、ヒントは「閉じる Esc」（`shortcutTip(…, 'close')`）。習慣の段のその日の一覧もスマホ幅は下からのシート
  - カードの操作の行（始まった予定は「記録して完了」、予定・Google の予定は「記録にする」・To‑Do の完了・終わっていなければ ▶ 記録を開始、`timeline/CardActions`）は題名・時刻のすぐ下、課題はその下
  - To‑Do のカードは時刻の下に、一覧の行と同じ締切（→| と近さの色、`ui/DueChip`。完了した To‑Do には出さない）・ラベル（● 名前）・タグを 1 行（`timeline/TaskCardMeta`）
  - タイルは置いた後なので先の締切は出さず、締切がその日まで（過ぎた・その予定では間に合わない・当日）の To‑Do だけ題名の前に →|（`calendar/TimeBlock`）
  - 色を選ぶ行は記録のカードだけ（色＝分類）
  - 予定・To‑Do の色は詳細の「色とラベル」で変える
  - Google の予定のカードは題名の左の色の四角（枠と ▾ のボタン、ヒントは「ラベル名（色名）」）を押すと色の一覧（`ColorPalette`）を出し、選んだ色を付ける。一覧の下の「Google の色に戻す」で付けた色を外す。色はアプリだけのもので Google には送らない（書き込めない予定にも付けられる）。繰り返しの予定はすべての回に付く。付けた色は似た題名の色の無い予定にも広がる（`lib/googleEventColors.ts`）。右クリックのメニューに色は無い（入口はカードだけ）。やらなかった予定には出さない
  - Google の予定の ▶ は予定の名前と色で記録を始める（元の To‑Do は無い）
  - 詳細はカードの ✎
  - カードに ⋮ は出さない（操作はカードのボタンと詳細）
  - 詳細（`TaskDetail`）の削除は右上の × の左の 🗑（スマホは上の帯の右）
  - 記録の詳細の時刻は To‑Do の実行日と同じ形で、記録した日の下に「開始 〜 終了」と長さを 1 段（終わりが開始以前なら翌日まで。日をまたぐ記録だけ終了日を出す、`detail/LogTimeFields`）
  - スマホ幅の月のマスは、どこを押してもその日の 1 日表示を開く

### Google カレンダー

- 設定の外部連携のページは Google カレンダーをそのまま出し、Notion と学校の LMS（Canvas・Moodle）は「その他の連携」の下に畳む。どちらかをつないでいれば開いて出す（`settings/MoreIntegrations.tsx`）
- Google カレンダーの接続中は日付の隣の緑の点だけ（乗せる・タップで「Google カレンダーに接続中」）。エラー時だけ赤い 1 行＋接続を解除（解除はどこからでも確認を出す）。接続・切断は `src/hooks/useGoogleConnect.ts`
- 未接続のカレンダーの「Google カレンダーの予定も並べて比べられます · 接続する」は × で閉じられ、閉じたら出さない（`googleConnectLineDismissed`、端末に保存）。接続は設定の「Google カレンダー」から
- Google の予定の時間はアプリから書き換えない（Google にある時間が開催時間）。時刻つきの Google の予定をドラッグで動かす・伸び縮みさせる・Alt+↑↓ でずらす・カードで日付と時刻を変えると、その予定の「自分の時間」になる（主催者でない・書き込みを許可していない予定も。予定の ID ごとで、繰り返しはその回だけ。「元に戻す」付き。`lib/myEventTimes.ts`）。開催時間と同じにしたら自分の時間を外す。終日の Google の予定・日をまたぐ予定のドラッグ・やらなかった予定は動かさない。題名・削除・コピーは今までどおり Google に反映する
- 自分の時間の予定は、週・3 日・日・月・スケジュール・日のパネル・今日の計画のどこでも自分の時間で並ぶ。空き時間・今と次の予定・記録にする（✓・カードの「記録にする」）も自分の時間（ストアの `calendarEvents` に入れるときに当てる、`withMyEventTimes`）。Google カレンダーでは開催時間のまま。カードには時刻の下に「開催 13:00–15:00」（日が違えば日付も）と「開催時間に戻す」を出す
- Google で開催時間が変わったら（取った予定の時間が自分の時間に持っている開催時間の控えと違えば）、自分の時間が新しい開催時間に収まっていればそのまま、はみ出した側だけ開催時間に合わせて削る（自分 13:30–15:00・開催が 13:00–14:30 になったら 13:30–14:30）。重ならなくなった・開催時間と同じになった・終日になったら自分の時間を外す（`fitMyTime`・`fitMyEventTimes`）
- Google カレンダーにつないで書き込みを許可していると、`GOOGLE_PUSH_UNTIL`（2026-10-27 0:00 JST）より前に作ったアプリの予定（To-Do でない予定）を直す・ゴミ箱に入れる・消すたびに Google の `primary` にも反映する（片方向。それより後に作った予定・To-Do・記録・睡眠は送らない。前に作った To-Do を予定にしても送らない。`src/hooks/useGooglePush.ts`・`src/lib/googlePush.ts`）
  - Google に入れたい予定は作成カードの作成先で「Google カレンダー」を選んで Google の予定として作る
  - 送るのは題名・日時・メモ・色（Google の 11 色のうち一番近い色。色なしはカレンダーの色）
  - タイムゾーンを決めた予定はそのタイムゾーンで送る
  - Google の予定の ID はアプリの予定の ID から決める（`chronograma`＋16 進）ので何度送っても 1 つで、この ID の Google の予定はカレンダーに Google の予定としては並べない
  - 送るのは変えた端末だけ（同期・ほかのタブで届いた変更は送らない）
  - 続けて直したものは 1.5 秒待って 1 回にまとめる
  - 変えた予定は Google につないでいれば（切れていても）端末の待ち（localStorage `chronograma.googlePush.{userId}`、`src/lib/googlePushQueue.ts`。タブ同士は読み込み→合わせて→書く）に入れ、送るのは書き込みを許可しているときだけ
  - 書き込めるかは予定の取得か関数の `status` で分かり、端末に覚える（`chronograma.googleCanWrite`）
  - 断られた理由は関数の `code` で分ける: 切れた・つながっていない・書き込みの許可が無いは待ちを残して止め、つなぎ直したら送る
  - 他人の予定はその 1 件だけ外す
  - 送りすぎ・回線の失敗は数えずに待つ
  - それ以外はその 1 件を飛ばして次を送り、5 回送れなければ自動では送らず、カレンダーの 1 行と設定の「Google カレンダー」に「Google に送れていない予定が N 件 · もう一度送る」を出す
  - タブを閉じるときに待たずに送るのは 20 件まで
  - 連携を外すと待ちは捨てる
  - つなぐ前に作った予定は送らない
  - Google 側で直した中身はアプリに戻らない
  - Google で消された予定はアプリでもゴミ箱に入れ（記録・To-Do は触らない）、「Google で消された予定を N 件ゴミ箱に移しました · 元に戻す」を出す
  - 5 件より多いときは先に確かめ、断られた予定は開いている間はもう聞かない（`src/lib/googleDeleted.ts`）
  - 見つけるのは予定の取得（関数が消された予定も取り、アプリの予定の分を `deletedPushed` で返す。まだ送っていない変更のある予定・消された後にアプリで変えた予定は除く）と送るとき（`google_deleted` で断られる）
  - 送るときに Google で消えていた予定は戻さない
  - 戻すのは、前は Google に置いていなかった予定（ゴミ箱から戻した・送らない名前から外したなど、待ちの `revive`）だけ
  - Google の予定をアプリで直そうとして消されていたら、一覧から外して「この予定は Google で削除されています」を出す
- 送らない名前（`user_addons.addons.googleSkip`、端末間で同期）の予定は Google に送らない（移動・面接対策のような段取りの予定）。作成先を名前から選ぶときはアプリだけの名前に数える
  - 名前は全角半角・大文字小文字・空白の違いだけ同じに数え、部分一致はしない（`src/lib/googleSkip.ts`）
  - ほかの端末から送らない名前が変わると、その名前の前に作った予定は Google から消し（日を問わない）、外れたら今日から先のその名前の前に作った予定を送る
  - 前に作った予定の名前を変えて送らない名前になれば消し、外れれば送る
  - アプリの中には送らない名前を変える操作は無い

### 計画どおり実行・ふりかえり・統計

- 「計画どおり実行」は終わった時間帯の予定だけで数える
- その日が来てから（今日・過ぎた日の）未完了の To-Do の予定日を別の日へ移すと、元の日・時刻と移した先を `movedPlans` に残す（1 件 30 個まで、`lib/movedPlans.ts`）。先の日どうしの付け替え・予定日を外す・完了した To-Do・子・予定は残さない。控えのある日へ戻したらその日の控えは消す。繰り返しの次の回には写さない
- 「計画どおり実行」の予定は時刻つきの To-Do と習慣の枠、その日から移した時刻つきの予定（やらなかった予定として分母に入る）
  - ✓ で終えた To-Do は記録が無くても計画どおり
  - 予定（授業・バイト）は記録との突き合わせには入れる（その時間の記録を予定に無かった記録にしない）が、分母には入れない
  - ▶ で始めた記録は元の To-Do（`sourceTaskId`）と先に組にし、残りを題名の似かたと時間の重なりで組にする（`matchEvents.ts`）
  - 日別の棒の予定の枠も同じ予定の集まりから数える
- 統計の日別の棒はラベルの色で積み、上に合計（`8h45` の短い形）、後ろに予定の時間を点線の枠で重ねる（塗るとラベルなしの灰色と見分けられない）
  - 「計画どおり実行」の下に「予定 N 件中 M 件」
  - 「記録した時間」の下に前の週との差（「先週より +1時間20分」「先週と同じ」。今週は前の週の同じ曜日までと比べる。色は付けず、前の週に記録が無ければ出さない、`getPrevReview`・`compareReviews`）
  - ラベル別の時間は 6 件までそのまま、7 件以上は上位 5 件＋その他
- ふりかえりの数字の枠は使っているものだけ: 時間に置いた予定の無い期間は「計画どおり実行」、習慣の予定の無い期間は習慣の達成を出さない。一度も記録していない人には、枠・棒・ラベル別・持ち越しを出さず一言だけ。統計に To-Do の未完了・締切切れ・連続の日の数は出さない（タグ別だけ）
- ふりかえりのラベル別の時間に、ラベルごとの予定した時間を並べる（`getReview` の `labelPlans`）
  - 予定のラベルは、その予定から ✓ / ▶ で作る記録と同じ: 時刻つきの To-Do・習慣の枠の色 → その色のラベル → 名前の無い色（`#RRGGBB`）→ 色の無い To-Do はラベルなし
  - 予定（授業・バイト）は入れない（日別の棒の予定の枠・「計画どおり実行」と同じ予定の集まりで、ラベル別の予定の合計は棒の予定の枠の合計と同じ）
  - 今日のこれからの予定も入れる
  - 予定のあるラベルは記録が 0 でも行を出し、行の下に細い線（点線の枠が予定、塗りが記録のラベルの色。超えた分も見えるよう長いほうに合わせる）と「予定 6時間」を文字で出す
  - 予定と目安のあるラベルは線を予定にし、目安は「記録 / 目安」の文字で出す
  - 週・月とも同じ
- ラベル別の時間の下に「予定に無かった記録」: どの予定（授業・バイトも含む）とも組にならなかった記録を、ラベルと題名（前後の空白は無視）ごとにまとめて多い順に 3 件（`unplanned`）。0 件の期間と、予定（時刻つきの To-Do・習慣の枠）の無い期間は出さない。週の日別の棒の読み上げ・ツールチップに、その日の予定に無かった記録の時間を足す
- ふりかえりの一言は、その期間の数字から作るいちばん大きいずれ 1 つ（`pickReviewInsight`・`reviewInsightText`）
  - 候補は分の大きさで比べる: ラベルの予定（時間の過ぎた分）と記録の差（1 時間以上かつ予定の 25% 以上。「ゼミは予定 6時間、記録 3時間でした。」）、予定に無かった記録でいちばん長いもの（1 時間以上、予定のある期間だけ）、時間を決めた予定が 3 件以上あってどれも記録・完了の無かった過ぎた日（その日の予定の長さ）、記録した時間の前の期間との差（1 時間以上かつ前の期間の 20% 以上。「先週より記録が 3時間 増えました。」）
  - 同じ大きさなら 記録の無かった日 → ラベル → 予定に無かった記録 → 前の期間との差、その中はラベル・日付の文字順（同じ数字なら同じ一言）
  - 候補が無ければ、時間を決めた予定が 3 件以上なら件数（「時間を決めた予定 4 件のうち、1 件を予定どおりに行いました。」）→ 記録の合計といちばん長いラベル → 終えた To-Do の数 → To-Do の数
  - 何も無い期間は、一度も記録したことが無い人にだけはじめの案内、記録したことのある人には「この週はまだ記録も予定もありません。」
  - 提案・原因の言い方はせず、文に矢印を使わない
  - 週・月とも同じ
- 設定「計画 › 1 日に使える時間」の下に、直近 2 週（昨日まで）の記録のある日の 1 日平均と日数（`recentDailyLoggedMinutes`）。記録が無ければ出さない
- ずれやすい曜日・時間帯は計算だけで、画面には出さない（`getPlanDriftCells`）: 最初の記録から 28 日たってから、昨日までの 28 日の「計画どおり実行」に数えた予定を、曜日 × 時間帯（始まりが 12:00 前 / 18:00 前 / それ以降）ごとに、予定の数・時刻がずれた数とずれの合計・記録の無かった数（✓ で終えたものは除く）で数える
- ふりかえりは見出しの「週 / 月」で切り替える（カードは 1 枚、切り替えると今週・今月に戻る、‹ › と K・J で 1 週・1 か月ずつ、T で今週・今月へ。`reviewPeriod.ts`・`getReview`）
  - 月はアプリのタイムゾーンの暦の月（1 日〜末日、今日まで）
  - 月では日別の棒の代わりに日のマスの濃さ（カレンダー形、並びは設定の週の開始日から。マスに記録の合計も出す。押すとその日の今日の計画）
  - 月の「記録した時間」は前の月との差（「先月より」、過ぎた月は「前の月より」）、ラベル別の時間の右に前の月との差（`+3h`・`±0`、色なし）
  - 今月は前の月の同じ日まで（短い月なら末日まで）と比べ、過ぎた月どうしは丸ごと
  - 前の月に記録が無ければ差は出さない（`getPrevReview`・`compareReviews`）
  - 月の「週に◯回」の習慣は 4 日以上がその月にある週（木曜がその月にある週）で数える
  - 「見積もりと記録」もその月に完了した To-Do
  - 「今月の完了」は月の「完了したタスク」で見て、統計のタスクの行には出さない
- ふりかえりは見出しの右の共有のアイコンから 1 枚の画像（PNG、幅 1080px）にして、ファイルを共有できる端末（スマホ）は端末の共有に、できない環境（PC のブラウザの多く）は保存する（`chronograma-review-YYYY-MM-DD.png`、月は `YYYY-MM`）
  - 画像は端末の中で `canvas` に描き、サーバーには送らない（`src/lib/reviewImage.ts`）
  - 入れるのは 見出し・期間の日付・記録した時間の合計・日ごとの棒（ラベルの色を `gc-dot` と同じ薄い塗り＋縁で隙間なく積む。週は曜日と棒の上の合計、月は日の数だけの細い棒で 1・8・15・22・29 日だけ日付）・ラベル別の時間の上位 5 件（7 件以上なら 6 件目からを「その他」）・選べば一言・右下に小さく「Chronograma」（URL は入れない）
  - To-Do・記録の題名とメモは入れない（一言の「予定に無かった記録」は題名の代わりにラベル名）
  - ライト・ダークは画面に合わせず、いつもライトで作る
  - 共有の前に見本を出し、「ラベル名を隠す（色と時間だけ。名前の代わりに長さの線）」と「一言を入れる」を選ぶ
  - ラベル名を隠すとラベルを名指しする一言は入れられない
  - ラベル名を隠すかは端末に覚える（`chronograma-review-share-v1`、同期しない）
  - 共有には代わりの文「今週の記録 18時間20分（ゼミ 6時間・就活 4時間…）」（上位 3 件、隠すときは合計だけ）を付け、見本の画像の代わりの文にも使う
  - 記録の無い期間はアイコンを押せない
- 日の違い（睡眠のページの直近 14 日のカードの下の段、`src/lib/dayInsights.ts`）: 昨日までの 28 日を、睡眠の長さ（6 時間未満 / 7 時間以上。間の日は入れない）・寝た時刻（0:00 より後 / 0:00 まで）・気分（◕● / ○◔。◑ は入れない）で 2 つに分け、1 つの分け方につき 1 行（最大 3 行、この順）
  - 比べる数字は記録した時間（1 日平均、記録のある日だけ）→ 予定どおり（ふりかえりと同じ数え方）→ 3 日以上に出てくるラベルの時間の順で、先に出せたもの
  - 夜は起きた日の分
  - 両側に 3 日以上あり、差が 2 割以上（かつ 15 分 / 10 ポイント以上）のものだけ出し、出せる行が無ければ段ごと出さない
  - 段の下に出す条件を 1 行添える
  - 提案・原因の言い方はしない
  - 直近 14 日に睡眠が無くても段が出せるなら、そのカードはこの段だけ出す

### 記録・タイマー・睡眠

- 記録中は、タイムラインの記録の列に始めた時刻から今まで伸びる枠を出す（止めたら入る記録と同じ日付・時刻・色。題名の前に赤い点、終わりの代わりに「記録中」。動かせない・押しても開かない。記録中の間だけ分の境目で描き直す。`runningLogTimes`）。止めると同じ場所が記録の枠になる
- 動いている記録のタイマーはアカウントで 1 つ（`user_active_timer`）。ほかの端末で始めたものもこの端末で止められる
  - 別の記録を始めると、動いていたものを記録にして止めてから始め、切り替えたことを知らせる
  - 1 分未満で止めたものは記録にしない
  - 元の To-Do が未完了なら、止めたあとに「「題名」を完了にしますか？」と聞く（`completePromptTaskId`。予定から始めた記録には聞かない）
  - 破棄は ⌘Z の履歴に入れず、破棄した 1 つをトーストから戻す（`restoreDiscardedTimer`。ほかの記録が動いていれば戻さない）
- ラベルを選ばずに記録したら推定して付ける（`inferLogCategory`。色を渡した記録には付けない）: 元の To-Do のラベル → 同じ題名で前回付けたラベル → 題名の単語が重なる過去の記録のラベル（重なりの多いもの、同じなら新しいもの）→ Google の予定の色と同じ色のラベル → 題名に入っているラベル名
- 記録パネルのタイマーは題名が空でも始められる（題名はラベル名、ラベルも無ければ「記録」）
- `?start=last`（ホーム画面のアイコンの長押しの「前回の記録を再開」、`lib/quickStart.ts`）は、終わりがいちばん新しい記録（睡眠・ゴミ箱・アーカイブ・題名の無いものを除く）の題名・ラベル・色・元の To-Do（まだあるときだけ）で始め、今日の計画を開いて知らせる
  - どの端末かを問わず記録中なら始めず、今日の計画を開くだけ
  - 記録が 1 つも無ければ始めずに知らせるだけ
  - ログイン中は最初の同期を待ってから決める（6 秒まで、`QUICK_START_SYNC_WAIT_MS`・`useQuickStartLaunch`）
- 記録を止めてラベルがなければ、完了の確認と同じ場所でよく使うラベルを 8 秒だけ聞く（完了の確認が出ているときは聞かない）。記録中はタブの題名に「▶ 0:42 題名」（終わりを付けていれば「▶ 残り 0:24 題名」）
- 浮いているタイマーは記録中に題名・ラベルを直せる: 題名を押すと欄（Enter・離れたで残し、Esc で戻す。空にはしない）、ラベル（無ければ「ラベル」）を押すと記録パネルと同じラベルのチップ（`TimeLogTagField`）。ラベルを選び直すと元の To-Do の名前の無い色は外す。止めた記録にそのまま入り、端末間で同じ（`editActiveTimer`）。止めたあとの「ラベルは？」（8 秒）はラベルなしで止めたときだけ
- 「あと何分」（集中タイマー）: 浮いているタイマーの「あと何分」から 25 / 50 / 90 分を選ぶ（予定・時刻のある To-Do から ▶ したときは、まだ来ていない予定の終わりも並べる）
  - 選ぶと表示は残り時間と「残り · 10:30 まで」、時間を過ぎたら「時間です」と過ぎた時間（+02:00）
  - 自動では止めない
  - 押すと選び直し・「終わりなし」で数え上げに戻す
  - 選ばなければ今までどおり数え上げ
  - 記録はふつうの記録 1 本（休憩・セットは持たない）
  - 終わりは端末間で同じ（`user_active_timer.ends_at`）
- 記録パネルの「後から記録」のボタンは今日だけ出す。今日は直前の記録（夜から続いた睡眠を含む、今日終わったもの）の終わり〜今（5 分に丸める）、無ければ今の 1 時間前〜今で開く。過ぎた日の記入漏れはタイムラインの「記録なし」の点線の枠から入れる
- 睡眠は睡眠の入力（今日の計画の睡眠の行・睡眠のページの図と一覧・睡眠のタイマー）と後から記録（記録パネル・タイムラインの記録の列）で作る
  - 後から記録は題名かラベルが「睡眠」「sleep」など（`looksLikeSleep`）なら睡眠にする
  - ▶ の記録・予定や To-Do を記録にしたもの・習慣のチェックでできた記録は、題名が「睡眠」でも記録のまま（#519）
  - 睡眠は追加機能にせず、いつも使える
  - 今日の計画の睡眠の行: 記録した行は行の終わりの薄い ✎ と一緒に行ごと押して直す
  - 記録のある夜を直す欄には 🗑（確認なしでゴミ箱へ、「10/25 (日) の睡眠を削除しました · 元に戻す」。睡眠の行・睡眠のページ・統計の睡眠の図で同じ `SleepTimesField`）
  - まだ記録の無い朝の欄は前回の時刻を薄い文字の下書きで入れ、長さは出さず、✓（睡眠の色の薄い塗り）で記録する
  - 時刻を変えると普通の文字と長さになる
- 睡眠のページ（`SleepView`、`?view=sleep`）
  - 今日の計画の睡眠の行の頭の ☾ と、統計の睡眠のカードから開く。サイドバー・下のタブには出さない
  - 開いている間は PC のサイドバーの「統計」、スマホの下のタブの「今日」を選んだ印にする
  - 統計の睡眠のカードは直近 14 日の平均の睡眠時間・☾ 寝た・日の出の印で起きただけ。睡眠の記録が 1 件も無ければ出さない
  - 上から: 直近 14 日（時計・平均とばらつき・夜ごとの図・日の違い）、週・月ごとの平均、夜ごとの一覧、睡眠の設定
  - 週・月ごとの平均: 今週〜3 週前（月曜はじまり、今週は今日まで）と今月〜2 か月前。睡眠・寝た・起きた・日数と、目標があれば目標との差。記録の無い期間は「記録なし」
  - その下に直近 28 日の土日（起きた日）と平日の寝た・起きた時刻の差。それぞれ 2 晩以上あるときだけ。15 分未満は「ほぼ同じ時刻」
  - 夜ごとの一覧: 新しい順に 30 晩ずつ、いちばん古い記録の夜まで。押すとその夜の下で直す・消す・記録の無い夜は入れる。目標に届かなかった夜に「目標 −◯」
  - 睡眠の設定は端末に保存し同期しない（`sleepPrefs`、`lib/sleepPrefs.ts`）
  - いつもの時刻: まだ記録の無い夜の欄に最初に入れる。決めなければ前回の睡眠の時刻。「決める」で前回の時刻から始め、「前回の時刻を使う」で外す
  - 目標の睡眠時間: なし・6〜9 時間を 30 分刻み
- 睡眠のタイマー（`lib/sleepTimer.ts`）: 今日を見ていて夜 20 時〜朝 5 時は睡眠の行に「寝る」を出す
  - 押すと寝た時刻を残し（記録のタイマーが動いていれば先に記録にして止める）、行は「23:30 から寝ています」と「起きた」・×（取り消し。「起きた」のすぐ隣。「元に戻す」付きで知らせる）になり、その朝の記録の行は上に残す
  - 「起きた」で寝た時刻〜今をその朝の睡眠にする（1 分未満は睡眠にしない）
  - 16 時間より長く寝たままなら今を起きた時刻にせず、寝た時刻を入れた欄で起きた時刻を聞く
  - 端末間で同じになり（`user_sleep_timer`）、止め忘れの通知は出さない
- 記録の無い時間（タイムラインの点線の枠・週のふりかえりの「記録なし」。どれも `unrecordedGaps`）は、記録・睡眠・動いているタイマーと、過ぎた予定（授業・バイト）の時間を埋まったものとして数える（予定は出たものとして扱う。記録した時間・ラベル別の時間には足さない）
  - 欠席にした回（時間割の欠席の印、`absentOnOf`）と時刻の無い予定は埋めない
  - Google カレンダーの予定は入れない
  - 起きた・寝た時刻は記録と睡眠だけで決める

### 習慣

- 習慣を作る・編集するフォームで最初に見せるのは 種類・名前・色・くり返し・「時間を決める」・「詳しく設定」だけ
  - 時間は決めていなければ「時間を決める」のボタン（押すと開始〜終了、既定は 09:00〜10:00）、決めたら欄の下に「終わりを外す / 終わりも決める」「時間を外す」（ルーティンは時間帯だけなので出さない）
  - 「曜日ごとに時間を変える」（時間を決めたとき）と「1 回の目標」（習慣だけ）は「詳しく設定」を開いたときだけ出し、どちらかを使っている習慣の編集では最初から開く（`AdvancedFields`）
  - 新しい習慣は時間なしから始める
- 習慣は 2 種類（`Habit.kind`、`habits.kind`）
  - 習慣（続けたいこと: ジム・英単語）と、ルーティン（毎日の予定のプリセット: ご飯・お風呂。`kind: 'routine'`）
  - 作る・編集のフォームの一番上の「種類」で選ぶ
  - ルーティンは時間帯だけ・毎日か曜日を指定だけ・1 回の目標なし（`effectiveHabitForm`。ほかを選んでいた値は残し、習慣に戻すと使う）
  - ルーティンはタイムラインに習慣と同じ枠で出し（✓・▶・その日だけ動かす・休むも同じ。自動で達成にしない）、今日の計画の習慣の行・習慣の画面の週の表と直近 4 週・連続・達成率・週のふりかえりの習慣の達成には入れない（`isHabitCountedOnDate` が false）
  - 「予定 N 件」・計画どおり実行・予定した時間には数えず、突き合わせには入れる（その時間の記録を予定に無かった記録にしない。枠の出どころは `routine`、`isUncountedPlanSource`。アプリと Edge Function で同じ）
  - 習慣の画面では週の表・直近 4 週の下の「ルーティン」に並べ、押すと詳細でいつもの時間からのずれ（直近 4 週の平均と、記録した日ごとの始めた時刻とずれを新しい日から 7 日。いつもの時間はその曜日の時間で、その日だけ動かした時間ではない。記録はその日のルーティンの記録 `habitRecordFor`。`lib/routineDrift.ts`）
  - 端末間で同期する
- 習慣の頻度は 毎日 / 曜日を指定 / 回数を指定（週に◯回、曜日は自由・週は月曜はじまり）。週に◯回はどの日も今日の計画に出し、その週の回数を満たした日は薄くして「今週は達成」。カードには「週に2回（今週 1/2）」と今週の回数を添える。連続は、曜日指定は予定のある日だけで数え、週に◯回は回数を満たした週の連続（「◯週連続」）
- 時間を決めた習慣は、フォームの「詳しく設定」の「曜日ごとに時間を変える」で曜日ごとの時間の行を出す（曜日を指定した習慣は選んだ曜日、毎日・週に◯回は 7 日。`formTimeDays`。押さなければ 1 つの時間。「どの曜日も同じ時間にする」で戻す）
  - 習慣は 1 つのままなので連続・達成率も 1 つ
  - 判定・タイムラインの枠・✓ の記録はその曜日の時間（`habitUsualTimesOn`）、その日だけ動かした時間がさらに優先
  - 一覧と詳細の 1 行は同じ時間の曜日をまとめる（「月・水 18:00〜19:00、土 10:00〜11:00」、毎日・週に◯回は頭に頻度）
  - 端末間で同期する（`habits.weekday_times`）
- 習慣には任意で「1 回の目標 ◯ 分以上」（1〜1440 分）を付けられる
  - 付けた習慣は、その日の習慣の記録（習慣につながった記録と同じ名前の記録。時間を決めた習慣は目標の時間帯の前後のもの）の合計が届いたら、チェックしていなくても達成（`habitDayStatus`・`habitMinutesOn`。時刻のずれは見ない）
  - 届かない日は未達成で、今日の計画の習慣の行の右に「12/30 分」、習慣の表のマスは読み上げとツールチップだけ
  - 手でチェックした日は今までどおり達成（時間を決めた習慣は予定の時刻で記録を作る。時刻ひとつの習慣の記録は目標の長さ、目標の無い習慣は 15 分。`plannedRecordTimes`）
  - 目標のある時間なしの習慣は ▶ で始めても達成にしない
  - チェックを外すとその日の記録もゴミ箱へ
  - 一覧の 1 行は「毎日 · 30 分」
  - 端末間で同期する（`habits.goal_minutes`）

### 追加欄

- 追加欄（To-Do・今日の計画・カレンダーの日のパネル）は、書いている間だけ下に詳細のチップ（実行日・時間・見積もり・締切・リスト・ラベル）を出す（`QuickAddDetails`）
  - チップには足したら付く値（書いた文・選んだ値・欄の既定を重ねた結果、`quickAddDraft`）を出し、押すと下に選ぶ面が開く
  - 選んだ値は書いた文より勝ち、消す・足すと空に戻る
  - チップを押しても入力欄のフォーカスは外さない（Enter でそのまま足せる）
  - いつか・チェックリストに入るなら日付のチップは出さない
  - 月のマスの小さい欄は読み取りの 1 行のまま

## 同期・保存

### 同期

- 送るのは取得した内容と違う行だけ（`updated_at` は比べない）。削除 100 件（版つきは 25 件）・保存 500 件ずつ
- 同期する行（リスト・セクション・タスク・習慣）の `updated_at` はサーバーが付ける。送る行には取得した版（`base_updated_at`、取得に無い行は `-infinity`）を付け、サーバーの行がその版のままのときだけ書く・消す（`004` の `sync_write_guard`）。断られた行は控えを取得した版にして、すぐ取り直して合わせ直す（続けて 3 回まで）
- 取得はふだん差分: 前回取得したサーバーの内容に、変わった行と消えた行の印（`sync_tombstones`）だけを当てる
  - 取得に無いだけの行は消えたとみなさない
  - 前回取得した内容と目印は保存の置き場所に残し（アプリの版と持ち主を付ける）、開き直しても差分で取る
  - この端末でこの人として初めて・残した内容が無い・6 時間ごと・前回の取得から 30 日・送った行が断られたとき・サーバーに行が 1 つも無いときは全部を取る
  - 前回同期した手元の行が印も無く無ければ、消さずに全部を取り直す（回数は 1 日 1 回 `reportSyncError` の `delta-miss`）
  - 差分の目印はサーバーに聞いた時刻（端末の時計は使わない）
- 1 回の取得は `sync_changes_since`（`035`）の 1 往復: 差分・印・版の下限・設定の表ごとの版・1 日の気分。設定は版が手元のもとにした版と同じで手元でも変えていなければ取りに行かない。関数が無い DB では 1 つずつ取る
- 1 分ごとの取得は、どれかのタブがその 1 分の間に同期していれば飛ばす（localStorage `chronograma-sync-done-at-v1:{userId}`）。画面に戻った・フォーカスが来たときは、同期中か 5 秒以内に同期していれば回さない
- 他の端末の変更は Realtime の通知（`038`、`src/lib/syncWake.ts`）で同期を起こしてすぐ取り込む
  - 通知は合図だけで、中身は差分で取る
  - 購読は本人の行の INSERT / UPDATE だけ（DELETE は RLS が効かない。消えた行は `sync_tombstones` の通知）
  - 通知は 0.5 秒まとめ、この端末がもう知っている版（前回の内容・設定のもとにした版・気分の `syncedAt` と同じ。自分が送った行のこだま）だけなら回さない
  - 同期中に届いた分は終わってから確かめる
  - 購読はタブが見えている間だけ
  - 購読できている間は取得を 5 分ごとに減らす（通知の取りこぼしの安全網）
- 合わせ方は項目ごと: 前回同期の控え（項目ごとのハッシュ）と比べ、片方だけが変えた項目はその側の値。両方が同じ項目を変えたときだけ時刻で比べ、手元の編集時刻はサーバーとの時計のずれ（送った行にサーバーが付けた時刻から測る、控えの `clockOffsetMs`）で直す。他の端末で消された・この端末で消した行が「その後変えられたか」も中身で見る（控えに項目が無いときだけ時刻）
- 両方が同じ項目を別の値にして新しいほうに任せた回数は `表.項目` ごとに端末にため、1 日 1 回 `reportSyncError` の `merge-conflicts` で送る（回数だけ。中身は送らない、`lib/mergeConflictReport.ts`）
- `order` で並べるところはすべて `compareByOrder`（`lib/orderCompare.ts`）。同じ `order` の行は id の文字コード順で、どの端末でも同じ並び
- 版を送らない書き込み（前の版のアプリ・`004` の前の DB）は前と同じく、サーバーの行より `updated_at` が古ければ捨てる
- ラベル表と他のタイムゾーン（利用者ごとに 1 行の設定）も `updated_at` はサーバーが付ける（`007` の `settings_write_guard`）。手元は「最後に変えた時刻」と「もとにしたサーバーの版」を持ち、手元だけ変えていれば送る・サーバーだけ変わっていれば合わせる。両方で変えたときだけ編集時刻を時計のずれで直して比べる（`lib/settingSync.ts`）
- 取り込み（Notion のデータベース名・フォルダを畳んだラベル）で作ったラベルは、ラベル表の変えた時刻を進めない。名前を `logLabelPendingAdds` に覚え、次の同期で合わせた表に無ければ後ろに足して送る（「無ければ足す」だけ。ほかの端末の名前・色・並びの編集はそのまま、`lib/labelSync.ts`）
- ラベル表は前回合わせた版にあったラベルの id を控える（本体と同じ置き場所 `chronograma-settings-base-v1:{userId}`、`saveSettingBase`）。両方の端末で変えた表を合わせるとき、控えにあって片方に無いラベルはその端末で消したので戻さない（もう一方でそのラベルを直していても消す）。控えが無ければ両方にあるものを残す
- 時間割・追加機能・よく入れる予定・授業と科目のつながりは、前回合わせた版の中身を同じ控えに持つ（ログアウトで消す）
  - 両方の端末で変えたときは中身ごとに三方向で合わせる（`lib/settingMerge.ts`）: 欠席は授業ごとの日付の集合、休める回数は授業ごと、時限・学期・祝日は項目ごと、機能のオン・オフは機能ごと、引き落とし・期限は id ごと、Google に送らない名前・欠席の一覧の授業は名前の集合、Google の予定に付けた色は予定・繰り返しごと、よく入れる予定は id ごと、つながりは予定の名前ごと
  - 片方だけが変えたものはその側、両方が別の値にしたものだけ新しいほう
  - 控えが無ければ両方にあるものを残す
  - 合わせた結果がサーバーと違えば送る
- やらなかった予定（`skippedEvents`、`045`）は中身の控えを持たない。両方の端末で変えた・この端末でまだ合わせていないときは予定の id ごとに両方を残し、どちらかで「削除」した予定は `removed` の印で消したままにする（`mergeSkipped`。片方の変更を捨てないので捨てた回数には数えない）
- Google の予定に付けた色（`googleEventColors`）は追加機能の設定と同じ行で同期する（`user_addons.addons.googleEventColors`。手元はストアの `googleEventColors` で、変えると追加機能の版 `addonsUpdatedAt` が進む）。色の無い値（前の版のアプリが送った）が届いたら手元の色のまま。持つのは付けた順の新しい 300 件まで
- Google の予定の自分の時間（`myEventTimes`、`user_my_event_times`、`049`）は中身の控えを持たない。両方の端末で変えた・この端末でまだ合わせていないときは予定の id ごとに変えた時刻（`updatedAt`）の新しいほうを取る。開催時間に戻したものは `removed` の印で 30 日残す（`mergeMyEventTimes`。捨てた回数には数えない）。持つのは開始の新しい 500 件まで、終わって 180 日たったものは落とす
- 行の中の集まり（習慣の日ごとの時間 `timeOverrides`・To-Do の移した予定 `movedPlans`）も、前回同期の控え（`habitTimeOverrides`・`taskMovedPlans`）と比べて日ごとに合わせる。控えに無い古い控えなら項目ごと新しいほう
- 設定を両方の端末で変えて片方を捨てた回数も `settings.<設定の名前>` で同じ記録に入れる（中身ごとに合わせる設定は捨てた数、合わせない設定は 1 回）
- セクションを消すと中のタスクはセクションを外すだけで `updatedAt` は変えない。サーバーではセクションの削除で外部キー（on delete set null）が外すので、同期はその行を送らない（`pushListsTasksHabits` は消すセクションを指すサーバーの行を外したものとして比べる）
- 同期は変わっていない行（同じオブジェクト）を文字列・ハッシュにして比べ直さない。行ごとの項目ハッシュは行ごとに覚え、前回と同じ内容（同じ配列・同じ時計のずれ）なら前回同期の控えを書き直さない。取得した行はこの端末のタイムゾーンの書き方にそろえてから前回の内容に入れる
- ログインせずに使っていた端末の初回同期: 中身の無い「いつか」「買い物」はアカウントに同じものがあれば外す。手元にサーバーに無いリスト・セクションがあれば合わせて残す
- 持ち主の記録が無い古いデータ（`*legacy*`）は、その人として同期した控えがあればその人のもの。ほかの人の控えしか無ければ外す

### 端末への保存

- 他タブの保存は BroadcastChannel（localStorage のときは storage イベント）で知って IndexedDB から読み直して取り込み（表示中の画面はタブごと）、同期は Web Locks でタブ間 1 本ずつ
- 端末への保存はストアが変わったとき。保存するデータがどれも前と同じ参照なら文字列にしない（`createPersistStorage`）。タスク詳細のメモ・場所は手元の書きかけで持ち、打つのが 0.6 秒止まったとき・欄を離れたとき・詳細を閉じたとき・タブを閉じる / 裏に回る / 読み込み直すときにストアへ入れる（`useDraftField`・`lib/pendingEdits.ts`）。書きかけの間に他のタブの保存を取り込んでも、書きかけはその項目だけ当たる
- 前回同期の控えと設定の版・版の中身の控え（どこまでサーバーと合わせたか）は本体と同じトランザクションで書く。本体を前のトランザクションで書いている途中なら、本体もいまの値で一緒に書き直す（`dataStore.ts`）。本体を保存できていない間（容量不足）は控えを書かず、設定も合わせない。同期を始める前に、本体・控え・設定の版を IndexedDB から読み直す
- 端末の保存領域が一杯なら取り込みの控え・保存データの写し・前回取得したサーバーの内容・ログイン中の人以外の前回同期の控えの中身を手放して再試行、まだ足りなければ自動バックアップを古いものから 1 つずつ手放して再試行（いちばん新しい 1 件は残す）、だめなら書き出しボタン付きのバナー
- IndexedDB との接続が切れたら（iOS の Safari が裏に長く回したあとに落とす・新しい版のタブが開き直す）1 回開き直して書き直す。開き直せなければ「保存先との接続が切れた・再読み込みしてください」のバナー（容量不足とは別）を出し、その後の変更は localStorage `chronograma-data-unsaved` に置いて次に開いたときに書く（`reportFailure` の `storage` / `connection-lost`）
- 一度 IndexedDB で開けた端末（localStorage `chronograma-data-in-indexeddb`）で開けなかったときは、空のまま書き始めない。保存と同期を止め（`blockPersisting('unavailable')`）、「保存データを開けなかった・再読み込みしてください」のバナーを出す
- 新しい版への読み込み直し・他のタブの新しい版での読み込み直しは、書いている途中の保存を書き終えてから（`reloadWhenSaved`、3 秒まで待つ）
- 移した後に localStorage で動いた回を取り込むとき、IndexedDB の本体にだけある行のうち、置き換える前の控えにあってその回の控えに無い行（その回で完全に消した・ほかの端末で消された行）は戻さない（`dropRowsDeletedInRecovered`）
- 保存データが読めないときは別キーに退避し、エラー画面に「書き出す」「自動バックアップから戻す」。退避した写し（`chronograma-storage-unreadable-{時刻}`・`-before-recovery-{時刻}`）は種類ごとに新しい 1 つだけ残す（`lib/deviceCleanup.ts`）
- ゴミ箱に入れて 30 日（`TRASH_KEEP_DAYS`）たったタスク・習慣は起動時に完全に削除し、同期でサーバーからも消す。ゴミ箱の件数の横に「30 日後に自動で削除」

### バックアップ・取り込み・書き出し

- バックアップの取り込みは全項目を検査・補完し、今編集したものとして刻む。知っている項目だけを取り出す（知らない項目はストアに入れない）。取り込むファイル（JSON・CSV）は読む前に大きさを確かめ、20 MB を超えたら読まない（`MAX_IMPORT_FILE_BYTES`）
- バックアップの JSON は、中身が食い違えば何も取り込まず、どこが悪いかを例の名前つきで出す（`readBackupJson`、`lib/backupFormat.ts`）: このアプリより新しい版・必須の項目が欠けた行・同じ ID が 2 回以上（タスク・リスト・セクション）・ファイルに無いリストを指すタスクやセクション・無いか別のリストのセクションを指すタスク・無い親を指すサブタスク
- 書き出しのファイル名は `chronograma-backup-YYYY-MM-DD.json`
- 保存する値（`DATA_KEYS`）は、書き出し（JSON・自動バックアップ・取り込みの控え）に入れる（`BACKUP_KEYS`）か、入れない理由を書く（`BACKUP_EXCLUDED`）かのどちらか。`backupKeys.test.ts` が確かめる。保存する値を足したらどちらかに入れる
- 書き出しの版は 4（`BACKUP_SCHEMA_VERSION`）: タスク・リスト・習慣・セクション・ラベル表のほかに、1 日の気分・時間割（欠席・休める回数）・追加機能（引き落とし・期限・学校の学期と授業・前の版の欠席の一覧の授業・Google に送らない名前）・よく入れる予定・授業と科目のつながり・他のタイムゾーン・端末の設定（`prefs`: テーマ・週の開始日・1 日の空き時間・ブロックの既定の長さ・予定の前の通知・アプリのタイムゾーン）
  - 気分のもとにしたサーバーの版は書かない
- 取り込みはファイルにある値だけ置き換え、無い値（前の版のファイル）は今のまま。気分は日ごとに置き換える。端末の設定は取り込まない（この端末の値のまま）。自動バックアップから戻すときは、控えにあって今は無いもの（日・授業の欠席の日・支払い・名前・よく入れる予定・つながり・タイムゾーン）だけを足す
- ログアウトの前・毎日の自動バックアップは、タスク・習慣が無くても気分・時間割・追加機能・よく入れる予定・つながり・他のタイムゾーンがあれば取る（`hasSettingsData`）
- 設定「データ › ほかのアプリから取り込む（TickTick・Todoist・CSV）」は今の To-Do に足す。見出しは先頭 10 行から題名の列がある行を探す（TickTick のバックアップは上に説明行がある）
  - TickTick: Title・Content（メモ）・List Name・Tags・Due Date・Priority（0 なし・1 低・3 中・5 高）・Status（1・2 は完了）・Completed Time。日時は UTC（`+0000`、時差の無いものも UTC）。終日（Is All Day）は行の Timezone の日付だけ、時刻つきはアプリのタイムゾーンの日付と時刻
  - Todoist: TYPE が task の行だけ（section・note・空行は読まない）。CONTENT が題名で、中の `@名前` はタグにして題名から外す。PRIORITY は 1 高・2 中・3 低・4 なし。DATE（無ければ DEADLINE）を締切に、時刻があれば締切の時刻に。「every day」のような言葉の日付は入れない。プロジェクト名はファイル名（末尾の ` [数字]` を除く）
  - リスト名は、同じ名前のリスト → 同じ名前のラベル（大文字小文字は問わない）の色 → どちらも無ければ取り込む前に「ラベルを作る / ラベルなしで入れる / 取消」を名前と件数つきで聞く。Inbox・受信箱はラベルなし
- 取り込み前の控えは 7 日（`IMPORT_ROLLBACK_KEEP_DAYS`）で捨てる。控えには持ち主（取り込んだときの `dataOwner`）を付ける
- 設定「データ › 記録を書き出す」: 期間（今週・今月・先月・すべて。週は月曜はじまり、開始日で切る）を選んで CSV か ICS に（手元のデータから作り、サーバーは使わない、`lib/recordExport.ts`）
  - CSV は UTF-8 BOM・CRLF、列は 種類・日付・開始・終了・終了日（日をまたぐときだけ）・分・ラベル・タイトル・タグ・元の予定（ふりかえりと同じ予定の集まりと突き合わせた「予定どおり / 時間がずれた / 予定になし」）
  - 見出しと値は画面の言語で、日付・タイトル・タグの見出しは CSV の取り込みでそのまま読める
  - 日付・時刻はアプリのタイムゾーン、分は実際の長さ（夏時間も）
  - 記録と睡眠を入れ、スイッチを入れたときだけ予定と ✓ で終えた時刻つきの To-Do も入れる（いつか・チェックリストは入れない）
  - 題名・ラベル・タグが = + - @ で始まるなら先頭に ' を付ける
  - ICS は記録だけ（`VEVENT` に `SUMMARY`・`CATEGORIES` にラベル、時刻は UTC の `Z`、`UID` は記録の id から作るので書き出し直しても重ならない）
  - 書き出すものが 0 件ならボタンを押せない（ICS は記録が 0 件なら）
  - ファイル名は `chronograma-records-YYYY-MM-DD.csv / .ics`
- 自動バックアップには持ち主（控えたときの `dataOwner`）を付け、一覧・復元はいまの人の分だけ（`canViewBackup`）。ログアウト後の端末では前の人の控えは見えない。持ち主の分からない古い控えはログイン中だけ。残す数は持ち主ごと。いま使っている人以外の控えは 30 日（`OTHER_OWNER_KEEP_DAYS`）で消す（持ち主の分からない控えは数だけ）
- 毎日の自動バックアップは、その日の分があるかを日付の索引（`chronograma-backups` の `dateKey`）で確かめてから全データを文字列にする。同期で手元のタスクが減るときの控え（同期の直前）は 10 分に 1 回まで。控えの中身の合計は 5,000 万文字まで（超えたら古いものから外し、いちばん新しい 1 件は残す。`MAX_TOTAL_CHARS`）

### ログアウト

- ログアウトは先に送ってから（クラウドの同期と、連携への送り待ち: Google カレンダーに送る予定・Notion のステータスを進める・Canvas の完了の書き戻し。`lib/integrationWrites.ts`）。送れずに残ったときだけ確認し、連携は名前と件数を出す。サーバーで切れなければ端末のセッションだけ消す
- ログアウトでは、保存データの写し・連携（Canvas・Notion）の前回取り込んだ値・Canvas の提出済みの控え・連携への送り待ち（Google・Notion・Canvas）・設定の前回合わせた版の中身の控えを誰の分も消し、前回同期の控えは中身を消して印（`null`）だけ残す（ほかの人として同期したことだけ分かる。`clearSignedOutLeftovers`）

### 繰り返しタスク

- 繰り返しタスクの次回の id は「元の id@締切日」
- 毎週の繰り返しは曜日（`weekdays`、1=月 … 7=日）を持てる。次回は選んだ曜日のうち締切の次に来る日、週の最後の曜日の後は間隔ぶん先の週の最初の曜日。曜日が無ければ締切の曜日で回る。やる日は締切と同じ日数だけずらす

### 連携

- 学校の LMS は「Canvas・Moodle」の欄で LMS を選んでつなぐ
  - Canvas はアクセストークンかカレンダーフィードの URL（`…/feeds/calendars/….ics`）、Moodle はカレンダーの書き出しの URL（`…/calendar/export_execute.php?userid=…&authtoken=…`、サブパスに置いた Moodle も可）
  - フィードと書き出しは読むだけで、Canvas のフィードと同じ間隔で取り込む
  - Moodle の書き出しは範囲を「すべての予定・最近と今後」に書き換えて読み（`userid`・`authtoken` 以外は捨てる）、科目の予定（CATEGORIES あり）の長さ 0 のもの（課題の期限・小テストの終了など）を締切つきの To-Do にし、科目の短い名前をタグにする
  - 件名が「開始」「opens」で終わるものは締切ではないので読まない
  - `TZID` 付き・浮動の日時はそのタイムゾーン（浮動・読めない名前はアプリのタイムゾーン）の時刻として期限にする（`supabase/functions/canvas/moodle.ts`・`feedUrl.ts`）
- トークンでつないだ Canvas の課題は、採点済み・免除・Canvas で完了にしたものだけ自動で完了にする（先生がやり直しを頼んでいれば済んでいない）
  - 提出しただけ（途中保存・下書きも Canvas は提出にする）は未完了のまま、行に「提出済み」を出す
  - 新しく提出済みになったものは、取り込みの直後に画面の下で 1 回だけ「終わりましたか？［完了にする］［まだ］」と聞く（何件か一度ならまとめて 1 回。答えなければ 12 秒で閉じる。見ているタブだけ数える）
  - 提出済みは端末間で同期せず、この端末に人ごとに覚える（`lib/canvasSubmitted.ts`、`CanvasSubmittedToast`）
- Canvas・Moodle の接続は 1 人 5 校まで。学校のサイトの応答は 5 MB まで読む（`canvas/body.ts`）。名前が引けない・内部を指す宛先には送らない
- Edge Function の呼び出しは利用者ごとに 10 分あたり Google 600・Notion 300・Canvas 300 回まで、Canvas の接続は 1 時間 20 回・アカウントの削除は 1 時間 10 回まで（`_shared/rateLimit.ts`）。超えると 429 で、Notion / Canvas は `*_rate_limited` の文言。数えられないとき（`hit_rate_limit` の失敗）も 429 で止める
- Google が断った理由は本文の `reason` で分ける（`supabase/functions/google-calendar/googleError.ts`）。利用上限（403 の `rateLimitExceeded` / `userRateLimitExceeded` / `quotaExceeded` / `dailyLimitExceeded`、429）は 429 の `google_rate_limited` で連携を残す（予定の読み取りは一度だけ待ってやり直す）。取り消し・期限切れ（`invalid_grant`・401）と許可不足（`insufficientPermissions`）は 409 でつなぎ直し、他人の予定は 409 の `google_read_only`、それ以外は 502 で連携を残す

### 行の上限

- DB の行には大きさの上限（タイトル 2000 字・メモ 20 万字・場所 2000 字・リストとセクションの名前 500 字・記録の分類 200 字など、`001_chronograma_schema.sql` の `*_size_check`）。入力欄はその長さまでしか書けない（`maxLength`、`src/lib/textLimits.ts`）。送るときには切らない。超えた行（取り込みなど）はその行だけ断られ、同期の表示は「N 件 未保存」
- 1 人が持てる行数にも上限（タスク・記録 20 万・セクション 5,000・リスト 1,000・習慣 1,000・Web Push の購読 100、`006_row_limits.sql`）。既にある行の更新は止めない。超えると同期は「未同期」のまま、ツールチップで上限に達したことを伝える

### 通知から開く・エラー・新しい版

- 通知の「予定どおり」で開いた URL だけ確かめずに記録する（Cache Storage の 1 回きりの印）。印の無いリンクは記録の画面を開くだけ
- 画面のエラー・拾われなかったエラー・同期の失敗・部品の読み込みの失敗・端末の保存（`storage`）・連携（`integration`）・通知の購読（`push`）の失敗は `client_errors` に送る（`src/lib/errorReport.ts`。保存・連携・購読は `reportFailure(kind, stage, error)`、中身は渡さず段階・表や項目の名前・数・メッセージだけ）
  - ログインしていない間・オフラインの間は端末に新しい 10 件までためて、ログイン・回線が戻ったら送る
  - 同じエラーは 10 分に 1 回・1 時間に 20 件まで、回線の失敗は送らない
  - URL はパスと `?view=` だけ、トークン・メールアドレスは伏せる
- 新しい版は戻ったときに確認し、切り替わったら画面が隠れたときに再読み込み。デプロイ直後の古いタブは 1 回だけ再読み込み（オフラインではしない）。遅れて読む画面・詳細・メニューが読めなかったら、詳細・メニューは何も出さずに「開けませんでした」と知らせて次に押したときに読み直し、画面は「もう一度」で読み直す
