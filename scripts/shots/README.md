# UI 撮影（scripts/shots）

原則 9「自分で画面を見て確かめる」を 1 コマンドにしたもの。
各画面を **デスクトップ / スマホ × ライト / ダーク** で撮って `.shots/`（git 管理外）に置く。

```bash
npm run shots                        # 全部（10 画面 × 2 幅 × 2 テーマ = 40 枚）
npm run shots -- --only=planner,stats
npm run shots -- --dark-only
npm run shots -- --out=/tmp/shots
```

**本番ビルドを撮る**（`npm run build` → `preview`）。dev サーバーだと
`import.meta.env.DEV` の開発者向け表示（Google OAuth の設定手順）が
写り込み、利用者が見る画面と違ってしまうため。
サーバーは毎回この作業ツリーから起こし、5180 以降の空いているポートを使う。
開いている `localhost:5173` は使い回さない（別の worktree や別の作業の画面を撮ってしまうため）。

## 撮る画面

`capture.mjs` の `SCREENS`。今は 今日の計画 / To-Do / To-Do の色ラベル / カレンダー / 習慣 /
統計 / 設定 / いつか / 買い物 など（`SCREENS` を参照）。

## 種データ

`seed.mjs`。空の画面を撮っても意味がないので、想定ユーザー（学生・就活生）
に合わせて 課題 / ES / バイト / ジム / 睡眠 を置く。
日付は撮影時刻から組み立てるので、「期限切れ」「今日まで」「近日中」が
毎回同じ構図で出る。

変えるときの注意:

- **`PERSIST_VERSION` は `taskStore.ts` の `version` と合わせる。**
  ずれると migrate が走って構図が変わる
- 日付は**ブラウザのタイムゾーン**（`capture.mjs` の `TIMEZONE`）で作る。
  ホストの時刻で作ると 1 日ずれて、予定・記録がタイムラインから消える
- 種は `addInitScript` でアプリが動く前に入れる。`goto` の後に
  `localStorage.setItem` しても、起動した store が作りたての state を
  先に保存して上書きしてしまう

## 見るときに気をつけること

- **左端の切れ端**: `deviceScaleFactor: 2` だと固定サイドバーの左に
  描画の残りが写ることがある。アプリの不具合ではない（1x では出ない）
- アプリは `body` が `overflow:hidden` で、スクロールするのは内側のペイン。
  そのため `fullPage` は使わない（固定サイドバーが縦に継ぎ足されて壊れる）
- ログインが要る表示（同期インジケータなど）は**撮れない**。
  認証なしのローカル専用として起動するため

## 未カバー

- ログイン後の画面（同期の状態表示・エラー）
- 時間経過で出るもの（止め忘れタイマーの確認は 8 時間後）
- トースト類（操作してから数秒だけ出る）

これらは今も目視が必要。
